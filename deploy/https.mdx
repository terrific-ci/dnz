By default the dashboard and API listen on `127.0.0.1:8080`, reachable only from the server
itself. To open them from elsewhere, put an HTTPS reverse proxy in front. HTTPS is **required** for
*Sign in with Cloudflare*.

<Tabs>
  <Tab title="Caddy">
    Caddy gets and renews certificates by itself.

    ```text Caddyfile
    dns.example.com {
        reverse_proxy 127.0.0.1:8080
    }
    ```
  </Tab>
  <Tab title="nginx">
    ```nginx /etc/nginx/sites-available/dnz
    server {
        listen 443 ssl http2;
        server_name dns.example.com;
        # ssl_certificate ...; ssl_certificate_key ...;
        location / {
            proxy_pass http://127.0.0.1:8080;
            proxy_set_header Host $host;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
    ```
  </Tab>
  <Tab title="DNZ itself">
    With a certificate, DNZ serves the dashboard and API over HTTPS on port 443 itself, together
    with DNS over TLS, HTTPS, QUIC and HTTP/3:

    ```bash /etc/dnz/dnz.env
    DNZ_TLS_CERT=/etc/dnz/tls/dns.example.com.crt
    DNZ_TLS_KEY=/etc/dnz/tls/dns.example.com.key
    ```

    See [Encrypted DNS](/dns/encrypted-dns) for getting the certificate and the ports.
  </Tab>
</Tabs>

## Trust the proxy's forwarded address

Behind a reverse proxy, every request reaches DNZ from the proxy's address. DNZ takes the client's
address from the proxy's headers (`X-Forwarded-For`, else `X-Real-IP`, else `Forwarded: for=`),
but only from a proxy it trusts, since anyone else could claim any address. The audit log,
sessions, sign-in lockouts, dynamic DNS, views and blocklists (DoH) use it.

DNZ trusts three kinds of address:

- **Proxies it already knows.** You don't have to set anything for approved Traefik, Caddy and
  DNZ Proxy [proxies](/proxy/overview), active DNZ Proxy nodes or the Caddy and Traefik servers of
  Sites in DNS. DNZ trusts the address each one calls from, the addresses DNS answers with, and the
  Traefik API's host. It reads them again every 30 seconds and right after one changes.
- **Addresses you add** under **Settings → General → Trusted reverse proxies**, or from the terminal:

  ```bash
  dnz settings trusted-proxies --add 10.0.133.10
  ```

- **`DNZ_TRUSTED_PROXIES`**, which is added to the two above and shown read-only in the UI:

  ```bash /etc/dnz/dnz.env
  DNZ_TRUSTED_PROXIES=127.0.0.1,::1
  ```

Both take IPs and CIDRs. Name the proxy itself, not your whole LAN, because any device in a trusted
range could pretend to be someone else. In Docker, that is the proxy container's address (or a
small network that holds only the proxy).

<Tip>
  Don't know the proxy's address? Open the audit log or the health check. When requests carry these
  headers from an address DNZ doesn't trust, the health check warns "DNZ is behind a proxy it
  doesn't trust" (`proxy_trust`) with that address and the line to paste. The settings card and the
  audit log offer a **Trust** button for it. Entries recorded before you trust it keep the proxy's
  address.
</Tip>

## Notes

- HSTS is sent when DNZ is reached over HTTPS, directly or through a proxy that sends
  `X-Forwarded-Proto: https`.
- Behind a proxy, `/dns-query` (DNS over HTTPS) works through the plain HTTP port too, so DoH can
  sit behind the same reverse proxy.
- For [DNZ Proxy](/proxy/dnz-proxy) nodes, the proxy in front of DNZ must not buffer responses (DNZ
  sends `X-Accel-Buffering: no`).
- Other DNZ servers can only find this one on the [replication](/dns/replication) radar when its
  HTTP port listens on the network (`DNZ_HTTP_ADDR=0.0.0.0:8080`).
