title: "Prometheus and Grafana"
description: "Scrape DNZ's /metrics with Prometheus, import the Grafana dashboard and load the alert rules."
---

DNZ serves its counters at `/metrics` in the Prometheus text format. Prometheus scrapes them,
Grafana graphs them, and the alert rules that come with DNZ tell you when something is off. You run
Prometheus and Grafana wherever you like; they only need to reach DNZ.

What is in there:

- queries by source (local, cache, upstream, blocked…), response code, type and transport, and a
  latency histogram,
- the cache: hits, misses, stale answers, prefetches, evictions,
- every upstream's health, round-trip time and failures,
- blocked queries, RPZ hits, the per-client rate limit and response rate limiting,
- DNSSEC validation results and the recursive resolver,
- zone transfers, NOTIFY, secondary zones and dynamic updates,
- proxying on or off, proxies by kind, certificate expiry, DNZ Proxy nodes, Traefik and Caddy
  proxies, GeoDNS health checks and the Caddy/Traefik record syncs.

Metrics are **off by default**.

## Turn them on

Open **Settings → General → Prometheus metrics**, switch it on and pick where it is served:

| | Own listen address | HTTP API |
| --- | --- | --- |
| URL | `http://<address>/metrics`, e.g. port 9153 | `/metrics` next to the dashboard and API, HTTPS when DNZ has a certificate |
| Token | Only once you make one | Always |
| Good for | A port only Prometheus can reach | One port for everything |

**Make a token** creates a bearer token Prometheus sends with every scrape. It is shown once: copy
it. A scrape without it, or with the wrong one, gets `401`.

The card then shows a scrape config for Prometheus, filled in with DNZ's address as your browser
reaches it (change it to the address Prometheus uses), and a `curl` line to check it from the
Prometheus host.

The same from the terminal:

```bash
dnz settings metrics on --addr 0.0.0.0:9153    # own listen address
dnz settings metrics --new-token               # printed once
dnz settings metrics --api on                  # also at /metrics on the HTTP API
dnz settings metrics                           # where it is served, the token
```

Or in the config file, which applies until the settings are saved in the dashboard or the CLI:

```toml
[metrics]
enabled = true
addr = "0.0.0.0:9153"
api = false
token = "a-long-random-string"
```

<Warning>
  Without a token, anyone who reaches the own listen address can read the metrics (names of zones,
  upstreams, proxies and certificates are in the labels). Listen where only Prometheus can reach, or
  make a token.
</Warning>

## Scrape it

Add a job to `prometheus.yml` on the Prometheus server. With a token, keep it in a file only
Prometheus can read:

```yaml
scrape_configs:
  - job_name: dnz
    scheme: http                       # https for the HTTP API behind TLS
    metrics_path: /metrics
    authorization:
      credentials_file: /etc/prometheus/dnz-metrics-token
    static_configs:
      - targets: ['dns1.example.internal:9153']
```

Several DNZ servers go into the same job, one target each. In a [cluster](/deploy/cluster), scrape every node: each
serves its own counters (`dnz_build_info` carries its node id, `dnz_cluster_leader` and
`dnz_cluster_generation` its place in the cluster), and metrics settings saved on one node reach the
others within 15 seconds. Check it from the Prometheus host:

```bash
curl -s -H "Authorization: Bearer $TOKEN" http://dns1.example.internal:9153/metrics | head
```

## Prometheus and Grafana with Docker Compose

The [`monitoring/`](https://github.com/terrific-ci/dnz/tree/main/monitoring) folder on the public
repository has a compose file that runs Prometheus (with DNZ's alert rules) and Grafana (with the
dashboard and the data source already set up) for a DNZ that runs elsewhere:

```bash
curl -fsSL https://github.com/terrific-ci/dnz/archive/refs/heads/main.tar.gz \
  | tar -xz --strip-components=1 dnz-main/monitoring
cd monitoring
cp .env.example .env        # set DNZ_TARGET, DNZ_METRICS_TOKEN and GRAFANA_PASSWORD
docker compose up -d
```

`DNZ_TARGET` is `host:port` as Prometheus reaches DNZ: the own listen address, or the dashboard's
address with `DNZ_SCHEME=https` behind TLS. Grafana is on port 3000 (user `admin`), Prometheus on
9090.

## Grafana dashboard

Download the dashboard, import it (**Dashboards → New → Import**, upload the file) and pick your
Prometheus data source:

```bash
curl -fsSLO https://raw.githubusercontent.com/terrific-ci/dnz/main/monitoring/grafana/dnz-dashboard.json
```

The data source and the DNZ servers to show are variables at the top. It has rows for the overview (queries per second, cache hit ratio, SERVFAIL ratio, p95 latency, upstreams up,
soonest certificate expiry), queries, cache and upstreams, filtering and rate limits, DNSSEC and
recursion, zones and transfers, certificates and proxies, and the process.

## Alert rules

Download the rules next to `prometheus.yml`:

```bash
curl -fsSLO https://raw.githubusercontent.com/terrific-ci/dnz/main/monitoring/prometheus/dnz-alerts.yml
```

They cover:

| Alert | When |
| --- | --- |
| `DnzDown` | Prometheus cannot scrape DNZ |
| `DnzAllUpstreamsDown`, `DnzUpstreamDown` | Every upstream of a pool, or one upstream, is down |
| `DnzHighServfailRatio` | Over 5% of answers are SERVFAIL for 10 minutes |
| `DnzSlowAnswers` | Forwarded answers have a p95 over 500 ms |
| `DnzCertificateExpiringSoon`, `DnzCertificateExpiresVerySoon` | A certificate expires within 14 or 3 days |
| `DnzAcmeCertificateFailing` | Issuing or renewing an ACME certificate keeps failing |
| `DnzRateLimitingSpike`, `DnzResponseRateLimitingSpike` | Many queries over the per-client limit, or many answers limited by RRL |
| `DnzDnssecValidationFailures` | Answers keep failing DNSSEC validation |
| `DnzSecondaryZoneFailing`, `DnzSecondaryZoneExpiring` | A secondary zone cannot reach its primaries, or is about to expire |
| `DnzDomainExpiring`, `DnzDomainExpired` | A [monitored domain](/dns/domain-expiry) expires within 14 days, or has expired |
| `DnzProxyNodeDown`, `DnzTraefikDisconnected` | A DNZ Proxy node or a Traefik stopped reporting |
| `DnzProxyNodeDiskFull`, `DnzProxyNodeMemoryHigh` | A DNZ Proxy node has less than 5% disk free, or its container is above 90% of its memory limit (its machine above 95%) |
| `DnzHealthCheckFailing`, `DnzSyncFailing` | A GeoDNS health check, or a Caddy/Traefik record sync, fails |
| `DnzClusterNodeBehind`, `DnzClusterNoLeader` | A cluster node has not loaded the latest changes, or no node holds the leader lease |
| `DnzBackupFailing`, `DnzBackupOverdue` | [Backups](/admin/backups) to a target failed twice in a row, or a scheduled one is more than an hour overdue |
| `DnzHealthFindingFailing`, `DnzHealthFindingsStale` | A [health check](/admin/health-check) finding fails, or the health check stopped running |
| `DnzUptimeMonitorDown` | An [uptime monitor](/dashboard/uptime) has been down for 2 minutes |

Add the file to `rule_files` in `prometheus.yml`. The rules expect the job to be called `dnz`.

## Metrics reference

DNZ describes every metric it exports: each one comes with a `# HELP` line in the scrape output
(`curl …/metrics` as above). A few to start with:

| Metric | What it tells |
| --- | --- |
| `dnz_dns_queries_total{source,rcode,qtype,transport}` | Answered queries |
| `dnz_dns_request_duration_seconds{source}` | Latency histogram |
| `dnz_cache_hits_total`, `dnz_cache_misses_total` | Cache effectiveness |
| `dnz_upstream_up`, `dnz_upstream_rtt_seconds` | Upstream health and speed |
| `dnz_filter_blocked_total` | Blocked queries |
| `dnz_query_log_bytes`, `dnz_query_log_files` | This server's [query log](/dns/query-logs) day files: their size (WAL included) and how many days are kept |
| `dnz_query_log_searches_rejected_total`, `dnz_query_log_dropped_total` | Searches turned away with 429 because two were still running, and log entries dropped because the writer fell behind |
| `dnz_live_captures` | [Live captures](/dns/live-capture) running on this server |
| `dnz_ratelimit_limited_total`, `dnz_rrl_responses_total` | Rate limiting |
| `dnz_access_sign_ins_total` | Sign-ins to proxied routes (allowed, denied, failed) |
| `dnz_cloudflare_syncs_total`, `dnz_cloudflare_sync_records_total` | Local zones pushed to Cloudflare |
| `dnz_logpush_lines_total`, `dnz_logpush_failures_total` | Log push |
| `dnz_dnssec_validations_total{result}` | DNSSEC validation |
| `dnz_domain_expiry_days{zone,domain}` | Days until a [monitored domain](/dns/domain-expiry) expires |
| `dnz_certificate_expiry_timestamp_seconds` | Certificate expiry |
| `dnz_proxy_enabled`, `dnz_proxies{kind}` | Whether proxying is on (1), and approved proxies by kind (`traefik`, `dnz`, `caddy`) |
| `dnz_proxy_upstreams{protocol}` | Upstreams (Proxy → Upstreams, shared by every proxy) by kind of traffic: `http`, `tcp`, `udp` |
| `dnz_proxy_node_memory_bytes`, `dnz_proxy_node_cpu_ratio`, `dnz_proxy_node_cpus` `{proxy,node}` | A DNZ Proxy node's [server](/proxy/dnz-proxy#servers): its process's memory (RSS), its CPU use as a share (0 to 1) of the CPUs it may use, and those CPUs (container limit, else the machine's). Also `dnz_proxy_node_uptime_seconds`, `dnz_proxy_node_host_cpus` and `dnz_proxy_node_tcp_sockets` |
| `dnz_proxy_node_load1`, `…_load5`, `…_load15` `{proxy,node}` | The node's machine's load average |
| `dnz_proxy_node_host_memory_total_bytes`, `…_used_bytes`, `…_available_bytes` `{proxy,node}` | The node's machine's memory |
| `dnz_proxy_node_container_memory_used_bytes`, `…_limit_bytes` `{proxy,node}` | The node's container (or systemd unit) memory, counted like `docker stats`, and its limit |
| `dnz_proxy_node_disk_total_bytes`, `…_available_bytes` `{proxy,node,role,path}` | The node's state volume (`role="state"`) and its cache's disk tier (`role="cache"`, when on another volume) |
| `dnz_proxy_waiting_room_active`, `…_queued`, `…_max_active` `{proxy,node,middleware,host}` | A DNZ Proxy [waiting room](/proxy/dnz-proxy#waiting-room-dnzwaitingroom): visitors in, visitors in line, and the limit, per node and hostname. With Redis every node reports the shared totals: take the max, not the sum |
| `dnz_proxy_waf_hits_total` `{proxy,node,middleware,rule,action}` | Requests a DNZ Proxy [web application firewall](/proxy/waf) matched, by rule id and action (`block`: refused, `log`: only logged). Starts at 0 when a node restarts |
| `dnz_traefik_connected{proxy}`, `dnz_caddy_proxy_connected{proxy}` | 1 while a Traefik or Caddy proxy fetched its configuration in the last minute (`…_last_seen_timestamp_seconds` says when) |
| `dnz_caddy_sync_success{id,caddy,kind}` | [Sites in DNS](/integrations/caddy): 1 when the last sync worked, `kind` `caddy` or `traefik` (not proxies; `dnz_caddy_sync_timestamp_seconds` says when) |
| `dnz_health_findings{status}` | [Health check](/admin/health-check) findings by status |
| `dnz_uptime_up{monitor,kind}`, `dnz_uptime_response_seconds{monitor}`, `dnz_uptime_ratio_30d{monitor}` | [Uptime monitors](/dashboard/uptime): 1 while up (0 while down), the last check's response time, and the share of the last 30 days' checks it was up. Also `dnz_uptime_status`, `dnz_uptime_last_check_timestamp_seconds` and `dnz_uptime_open_incidents` |
| `dnz_dhcp_leases{server}`, `dnz_dhcp_read_success{server}` | DHCP servers' live leases, and whether DNZ can read them |
| `dnz_ipam_conflicts{division}` | What [IPAM](/integrations/dhcp#ipam) found that doesn't add up |

Labels never carry query names or client addresses, so the number of series stays small; query
types outside the common ones are counted as `other`.
