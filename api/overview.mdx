Everything the dashboard does goes through DNZ's HTTP API under `/api`. The [CLI](/cli/overview) uses
the same API. For automation (Terraform, scripts, CI, ACME DNS-01 certificates), use an
**API token**.

## API tokens

### Creating a token

<Tabs>
  <Tab title="Dashboard">

Go to **Settings → API tokens → Create token**. This needs the *Manage API tokens* permission
(`tokens.manage`), which the Owner role has.

  </Tab>
  <Tab title="CLI">

```bash
dnz token create certbot -p records.write,zones.read -z example.com --expires-in-days 90
```

See [API tokens](/cli/access#api-tokens) in the CLI reference.

  </Tab>
</Tabs>

A token has:

- **A division.** It can only reach zones in the division it was created in.
- **Permissions**: any of `zones.read`, `records.write`, `zones.write` and `logs.read`.
- **Zones**: every zone in the division, or only some. A token limited to some zones can't create new
  zones.
- **An expiry**: 30 days, 90 days, 1 year, or never.

The token (`dnz_…`) is shown **once**, when it is created. DNZ only stores its hash. If you lose it,
revoke it and create a new one.

### A token never has more rights than its creator

You can only give a token permissions you have yourself in that division. The rights are checked again
every time the token is used, so when the creator loses a right, the token loses it too.

Every change made with a token appears in the [audit log](/admin/audit-log) as
`<creator> via <token name>`.

### What a token can reach

Tokens can only call the **zone, record, query log, live capture and ACME** endpoints, the Dynamic DNS
endpoint, and pushing a DHCP server's lease file and reading leases and IPAM ([DHCP](/api/dhcp)). Account, user, role and settings endpoints always need a normal sign-in.

AI assistants that sign in over OAuth for MCP get tokens starting with `dnzo_` that act as the user who allowed them; see [AI assistants (MCP)](/integrations/ai-assistants#what-an-oauth-sign-in-may-do) for what they may call.

| Permission | Lets the token |
| --- | --- |
| `zones.read` | List zones, read records, tags and zone files, refresh secondary zones |
| `zones.write` | Create, change and delete zones |
| `records.write` | Create, change and delete records, ACME challenges and Dynamic DNS |
| `logs.read` | Read the query log of the division's zones and client networks ([Query logs API](/dns/query-logs#api)), and capture the division's queries live with `POST /api/capture` ([Live capture](/dns/live-capture#api)) |

## Authentication

Send the token as a **Bearer** token:

```bash
curl -H "Authorization: Bearer dnz_…" https://dns.example.com/api/token
```

HTTP **Basic** works too, with the token as the **password** and any username. This is what lego and
Traefik use:

```bash
curl -u "any:dnz_…" https://dns.example.com/api/token
```

`GET /api/token` answers with the token's name, division, permissions and the zones it can reach,
which makes it a handy check in scripts. See [Token info](/api/zones#token-info).

## Errors

Errors come back as JSON with an HTTP status:

```json
{ "error": "…" }
```

| Status | Meaning |
| --- | --- |
| `400` | The request is invalid: a bad value, a field missing, an id outside the zone |
| `401` | No valid token or session |
| `403` | The token or user lacks the permission |
| `404` | The zone or record doesn't exist |
| `409` | A conflict: a duplicate record, a CNAME next to other data |
| `429` | Too busy right now, for example a [query log search](/dns/query-logs#two-searches-at-a-time) while two others run on the server. Wait the seconds in `Retry-After` and try again |

## Long lists

Lists that can grow long come a page at a time. Ask with `page` (from 1) and `per_page` (50 by
default, at most 200; `limit` is read as `per_page`). The answer has `total`, `page` and `per_page`
next to the list. Filters and searches apply before the page is cut, so `total` is what matches.

| List | Path | Filters and search |
| --- | --- | --- |
| Change requests | `/api/changes` (`changes`) | `status`, `scope`, `zone_id`, `division_id` ([History and changes](/api/changes)) |
| Audit log | `/api/audit` | `q`: text in the user, action, target, details or address |
| Zone history | `/api/zones/{id}/versions` (`versions`) | – |
| Route history | `/api/proxies/{id}/route-history` (`versions`) | `host` |
| Threat findings | `/api/threats/findings`, `/api/threats/groups` | `q`: client or domain, and more ([Threats](/api/threats#listing-findings)) |
| Middlewares | `/api/proxy/middlewares` | `q`, `protocol`, `own`, `firewalls`, `unused` |
| Users | `/api/users` (`users`) | `q`: user name, name or email |
| Division members | `/api/divisions/{id}/members` (`members`) | `q`: user name, name, email or role |
| API tokens | `/api/divisions/{id}/tokens` (`tokens`) | `q`: name or prefix |
| Update keys | `/api/divisions/{id}/update-keys` (`keys`) | `q`: name |
| Zones | `/api/divisions/{id}/zones` (`zones`) | `q`: the name ([Zones](/api/zones#list-zones)) |
| A zone's records | `/api/zones/{id}/records` (`records`) | a page of **names**: `q`, `type`, `name`, `tag`, `enabled`, `view`, `proxied`; also `matching` and `facets` ([Records](/api/records#pages-of-names)) |
| A view's records | `/api/views/{id}/records` (`records`) | – |
| Filtering rules | `/api/filtering/rules` (`rules`) | `division_id`, `action` (`block` or `allow`), `q` ([Filtering](/api/filtering)) |
| DHCP leases | `/api/dhcp-servers/{id}/leases`, `/api/divisions/{id}/dhcp-leases` (`leases`) | `q`, `live` ([DHCP](/api/dhcp)) |
| A subnet's addresses | `/api/divisions/{id}/ipam/subnet?cidr=` (`addresses`) | – |
| Threat blocks | `/api/threats/blocks` (`blocks`) | – |
| Upstreams | `/api/proxy/upstreams` (`upstreams`) | `q`, `protocol`, `unused`, `own=hide`; also `counts` and `twins` ([Proxy](/api/proxy#upstreams)) |
| Certificates | `/api/acme/certificates` (`certificates`) | `q`, `state` ([Certificates](/api/certificates)) |
| DNZ Proxy nodes | `/api/proxy/dnz` (`nodes`) | `proxy_id`, `q`: name or address; nodes waiting for approval come whole in `pending` ([DNZ Proxy](/api/dnz-proxy)) |
| Status pages | `/api/status-pages` (`items`) | `q`: hostname, `state`; also `counts` ([Status pages](/api/status-pages)) |
| Uptime monitors | `/api/uptime/monitors` (`monitors`) | `q`, `status`; also `counts` ([Uptime](/api/uptime)) |
| Uptime incidents | `/api/uptime/incidents` (`items`) | `days`, `monitor`, `resolved` |
| Notification incidents | `/api/incidents` (`incidents`) | `source` (`dns` or `proxy`) |
| Backups made | `/api/backups/runs` (`runs`) | `target` ([Backups](/api/backups)) |
| Archives on a target | `/api/backups/targets/{id}/files` (`files`) | – |

The query log pages differently, without a total: see [Query logs → Pages in the
API](/dns/query-logs#pages-in-the-api).

```bash
curl -H "Authorization: Bearer $TOKEN" "https://dns.example.com/api/zones/3/versions?page=2&per_page=100"
```

<Note>
  Older clients keep working: a list that used to answer a bare array, or page with a `before` cursor,
  still answers that way when neither `page` nor `per_page` is given.
</Note>

## Example: adding a record

```bash
curl -X POST https://dns.example.com/api/zones/3/records \
  -H "Authorization: Bearer $DNZ_TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"app","type":"A","value":"192.0.2.20","ttl":300}'
```

Find a zone's id with `GET /api/divisions/{id}/zones`, or with `dnz --json zone list`.

<Tip>
  There is no DNZ Terraform provider yet. A generic REST provider works with these endpoints; see
  [Terraform](/integrations/terraform).
</Tip>
