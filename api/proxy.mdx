<Note>
  Every endpoint here needs a **superadmin** session, with two exceptions: `GET /api/proxies` works
  for any signed-in user (the record editor uses it), and the Traefik and Caddy endpoints take the
  connect key or a proxy's own token. See [API overview](/api/overview) for how to authenticate.
</Note>

For what these objects do, see [Proxied records](/proxy/overview),
[Connecting Traefik](/proxy/traefik), [Connecting Caddy](/proxy/caddy),
[Routers, services and middlewares](/proxy/routing) and
[Records from Traefik's routers](/proxy/traefik-records). DNZ Proxy nodes, entry points and analytics
are in the [DNZ Proxy API](/api/dnz-proxy). Read-only proxies (a Caddy or Traefik DNZ only reads)
have their own endpoints: see the [Read-only proxies API](/api/proxy-sites).

## Settings and proxies

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/settings/proxy` | `enabled`, `locked`, `kinds`, `traefik_path`, `caddy_path`, `connect_key`, `connect_key_locked`, `max_pending` and `proxies` (see below) |
| `PUT` | `/api/settings/proxy` | `{"enabled": true}` or `{"enabled": false}` |
| `POST` | `/api/settings/proxy/connect-key` | Replace the connect key (400 while `DNZ_PROXY_CONNECT_KEY` sets it) |
| `GET` | `/api/proxies` | `{"enabled": true, "proxies": [{"id", "name", "kind", "ipv4", "ipv6", "routes": [...]}]}`: approved proxies only, with their enabled routers |
| `POST` | `/api/proxies` | Add a proxy by its `kind` and addresses |
| `PUT` | `/api/proxies/{id}` | Change a proxy |
| `DELETE` | `/api/proxies/{id}` | Delete a proxy (409 while records use it) |
| `POST` | `/api/proxies/{id}/approve` | Approve a detected (or ignored) Traefik or Caddy, with a proxy body |
| `POST` | `/api/proxies/{id}/ignore` | Ignore a detected Traefik or Caddy |
| `POST` | `/api/proxies/{id}/link` | `{"proxy_id": 3}`: a detected Traefik or Caddy connects as that proxy from now on |
| `POST` | `/api/proxies/{id}/token` | Give the proxy a token of its own (shown once; replaces an earlier one) |
| `DELETE` | `/api/proxies/{id}/token` | Back to the connect key |
| `GET` | `/api/proxies/{id}/traefik` | Version, entry points and router status, from the proxy's Traefik API |
| `GET` | `/api/proxies/{id}/caddy` | `{"config", "warnings"}`: the configuration a Caddy proxy gets, and what was left out of it |
| `POST` | `/api/proxies/traefik-check` | Try a Traefik API before saving: `{"url", "user", "password"}` |

**Settings.** `GET /api/settings/proxy` returns:

| Field | Meaning |
| --- | --- |
| `enabled` | Whether proxying is on |
| `locked` | `true` when `DNZ_PROXY_BACKEND` sets it; `PUT` then can't change it |
| `kinds` | The kinds a proxy can have: `[{"kind", "label"}]`, with `traefik`, `dnz` and `caddy` |
| `traefik_path`, `caddy_path` | Where Traefik's HTTP provider and Caddy's config loader call |
| `connect_key` | The key every Traefik and Caddy calls with, and DNZ Proxy nodes join with |
| `connect_key_locked` | `true` when `DNZ_PROXY_CONNECT_KEY` sets the connect key |
| `max_pending` | How many detected proxies may wait at once |
| `proxies` | Every proxy, with its `kind`, status, routers and proxied hosts |

`backend` and `backend_locked` are gone. A `PUT` with the older `{"backend": …}` still works and reads
as on (`traefik`, `dnz`) or off.

## Routes, routers, services and middlewares

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/proxies/{id}/setup` | The proxy's routers, services and middlewares, and its proxied names |
| `GET` | `/api/proxies/{id}/routes/hosts` | What Add route offers: `{"zones": [...], "records": [{"host", "types", "routed"}]}`. DNZ's primary zones and the names with A/AAAA/CNAME records (`routed` when this proxy has a router for one) |
| `GET` | `/api/proxies/{id}/routes/entry-points` | The proxy's HTTP entry points for the router and Add route dialogs: `{"list": [{"name", "address"}], "http", "https", "from", "http_found", "https_found", "error"}` |
| `GET` | `/api/proxies/{id}/routes` | `{"routes": [...], "auto_certificates"}`: each route's `id` (its router), `hosts`, `path_prefix`, `tls`, `cert_resolver`, `redirect_router`, `service_id`, `service_name`, `own_service` (false: a service of the proxy's it uses), `servers`, `options` (the switches), other `middlewares`, `simple` / `advanced` and, on DNZ Proxy, `certificate`. One proxy's routes, whole |
| `GET` | `/api/proxy/routes` | [The Routes page](#the-routes-page): every approved proxy's routes, one row per hostname, filtered and paged on the server |
| `GET` | `/api/proxy/routes/targets` | Every route the same filters match, as the batch edit takes them (*Pick all matching*) |
| `POST` | `/api/proxies/{id}/routes` | One step: `{"host" or "hosts", "servers" or "service_id" (one of the proxy's services, used as it is), "tls", "redirect_http", "options", "middlewares", "path_prefix", "dns_record", "skip_tls_verify"}` adds the service, router(s), switches and proxied DNS records. `skip_tls_verify` is for the route's own HTTPS servers (see [Skip TLS verify](#skip-tls-verify)). With `dns_record` (the default) it is refused (409) in a zone whose changes wait for approval for you: it would write the records at once |
| `POST` | `/api/proxy/routes/bulk` | [Several routes at once](#several-routes-at-once), on any proxies, all or nothing |
| `PUT` | `/api/proxies/{id}/routes/{router}` | The same body: changes the route (409 for one set up under Advanced); also `"clear_redirect": true` |
| `DELETE` | `/api/proxies/{id}/routes/{router}[?unproxy=true]` | Deletes its routers, its own service (a picked one stays) and switches; `unproxy` takes the proxy off its DNS records instead of refusing |
| `GET` | `/api/proxies/{id}/route-history[?host=]` | The proxy's route versions, newest first; `/{version}` one with the route before and after; `POST …/{version}/restore` puts it back ([Route history](/proxy/route-history#api)) |
| `POST` / `PUT` / `DELETE` | `/api/proxies/{id}/routers[/{router}]` | Add, change, delete a router |
| `GET` / `POST` | `/api/proxy/middlewares` | Every proxy's [middlewares and firewalls](/proxy/middlewares), a page at a time (`?q=`, `protocol=http\|tcp`, `own=true` for routes' own switches, `firewalls=true`, `unused=true`), or add one (`{"name", "kind", "config", "protocol", "description"}`) |
| `GET` / `PUT` / `DELETE` | `/api/proxy/middlewares/{id}` | One middleware: show, change (`"shared": true` makes a route's own switch shared), delete (refused while anything uses it) |
| `GET` | `/api/proxy/middlewares/{id}/usage` | What uses it: routes per proxy, chains, route defaults |
| `POST` | `/api/proxy/middlewares/merge` | `{"keep", "merge": [ids]}`: everything using the others uses `keep`, and they are deleted |
| `POST` / `PUT` / `DELETE` | `/api/proxies/{id}/objects[/{object}]` | Add, change, delete a certificate, TLS options, the default store, or a TCP/UDP router or service |
| `POST` | `/api/proxy/auth-user` | A basic or digest auth user line from `{"user", "password"}` |

Since DNZ v2, `/api/proxies/{id}/services` and `/api/proxies/{id}/middlewares` answer `410 Gone` (use
`/api/proxy/upstreams` and `/api/proxy/middlewares`), and
the objects endpoint refuses transports (an upstream's connection settings, under
`/api/proxy/upstreams`) and TCP middlewares (`/api/proxy/middlewares` with `"protocol": "tcp"`).

**Entry points.** Under DNZ Proxy, `routes/entry-points` lists the proxy's own entry points. Under
Traefik it lists the ones its API lists. `from` says which (`dnz-proxy` / `traefik`). Without either,
and always under Caddy, it offers `web` (:80) and `websecure` (:443). `http` and `https` are the ones on port 80 and 443 that
a new route uses.

**Redirects.** `POST` and `PUT` on a route take `"redirect": {"to": "https://new.example.com",
"keep_path": true, "permanent": false}`: every visit to the route's hosts goes to `to` (a `moved`
[status page](/api/status-pages) on each, replacing another kind), and `servers` may be empty.
`permanent` defaults to `true` (301); `false` answers 302. `to` must be `http://` or `https://` and
not one of the route's hosts. `PUT` with `"clear_redirect": true` deletes the hosts' `moved` status.
Both answer with the statuses in `redirects`.

**Routes.** In `POST /api/proxies/{id}/routes`, `http_entry_point` and `https_entry_point` default
to the `http` and `https` entry points above, and `cert_resolver` to DNZ's automatic certificates on
DNZ Proxy (once set up). `options` holds the switches:

```json
{
  "cache": "10m",
  "firewall": 4,
  "challenge": true,
  "rate_limit": { "average": 100, "burst": 300 },
  "basic_auth": ["admin:$2y$05$…"],
  "allow_ips": ["10.0.0.0/8"],
  "waf": { "mode": "block", "sensitivity": "medium", "skip_paths": ["/admin/editor"], "skip_rules": ["xss-tags"], "allow_ips": ["192.0.2.0/24"] }
}
```

Each is the route's own middleware (`cache`, `firewall`, `challenge` and `waf` on DNZ Proxy only; `firewall`
names one of the firewalls, which every proxy shares). `waf` is the [web application firewall](/proxy/waf):
`mode` `block` (default) or `log`, `sensitivity` `low`, `medium` (default) or `high`, and up to 100
each of `skip_paths`, `skip_rules` (ids from `GET /api/proxy/waf/rules`) and `allow_ips`; a Traefik
or Caddy route with it gets `400`. A route's `certificate` has `state`, `not_after`,
`last_error`, `next_attempt_at` and its latest `events`.

**Auth users.** `POST /api/proxy/auth-user` with `{"user", "password"}` returns `{"line"}` for basic
auth. Add `"digest": true` and an optional `"realm"` for digest auth.

### Skip TLS verify

`"skip_tls_verify": true` on `POST` and `PUT` makes the proxies accept any certificate from the
route's own `https://` servers (the dialogs' **Skip TLS verify**); `false` checks that each server's
certificate is valid for its address. Left out, a new route accepts any certificate (as routes always
did) and an edited one keeps what its upstream has. `POST /api/zones/{id}/records/route` (the record
dialog's route) takes it too. A route that uses an upstream from the list follows that upstream's
[connection settings](/proxy/upstreams#connection-settings) instead.

```json
{ "host": "app.example.com", "servers": [{ "url": "https://10.0.0.10:8443", "weight": 1 }], "tls": true, "skip_tls_verify": false }
```

### The Routes page

`GET /api/proxy/routes` is **Proxy → Routes** ([Using it](/proxy/overview#adding-a-route)): every
approved proxy's routes (HTTP, TCP and UDP), one row per hostname (and path), searched, filtered and
paged on the server, so `total` and every count are over every route.

| Parameter | |
| --- | --- |
| `q` | Text in a hostname, the path, an upstream address, the group's or a proxy's name |
| `proxy` | A proxy's id or name: only its copies (a route's copies on the other proxies come in `others`) |
| `type` | `on`, `off`, `redirect`, `https`, `http`, `cert-failing`, `dns-missing`, `advanced`, or a switch: `cache`, `firewall`, `waf`, `under-attack`, `waiting-room`, `rate-limit`, `password`, `sign-in`, `allow`, `headers`, `uploads`, `rules` |
| `group`, `zone` | A route group's or a zone's name, or `-` for routes in none |
| `view` | `zones` or `groups`: rows ordered by zone or group, and each one's count in `groups` |
| `page`, `per_page` | 50 a page by default, at most 200 |

```json
{
  "rows": [
    {
      "key": "app.example.com",
      "hosts": ["app.example.com"],
      "path": "",
      "zone": "example.com",
      "group": "Web app",
      "entries": [{ "proxy_id": 1, "route": { "id": 12, "hosts": ["app.example.com"], "tls": true } }],
      "others": []
    }
  ],
  "total": 1240,
  "page": 1,
  "per_page": 50,
  "unfiltered": 1240,
  "proxies": [{ "id": 1, "name": "edge", "kind": "dnz", "auto_certificates": true, "proxied": [], "checks": {} }],
  "middlewares": []
}
```

- `entries` holds each proxy's copy of the route as `GET /api/proxies/{id}/routes` shows it, with
  its certificate and latest steps on a DNZ Proxy (shortened above).
- `unfiltered` counts the rows before the search and filters (the proxy filter applied).
- `proxies` lists each proxy's `name`, `kind` and `auto_certificates`, and for the page's routes the
  names DNS answers with it (`proxied`) and the last reachability `checks` (by route id).
- `middlewares` holds the shared middlewares and those the page's routes name.
- `groups`, only with `view=zones` or `groups`, is `[{"name", "count"}]` (`name` is `null` for routes
  in none): a zone or group can run on over several pages, and its count is its whole one.

Both need **Manage proxies** (`proxy.manage`).

`GET /api/proxy/routes/targets` takes the same filters and answers every route they match, as
`POST /api/proxy/routes/bulk` takes them: `{"routes": [{"proxy_id", "id"}], "rows": [{"key", "hosts",
"path", "group", "entries": [{"proxy_id", "id", "protocol", "enabled"}]}], "total", "count", "limit",
"over"}`. Past 5,000 routes `over` is `true` and nothing is listed.

```bash
curl -H "Authorization: Bearer $TOKEN" "https://dns.example.com/api/proxy/routes?q=shop&type=https&view=zones&page=2"
```

### Several routes at once

`POST /api/proxy/routes/bulk` is the Routes page's bar
([Several routes at once](/proxy/overview#several-routes-at-once)): operations, in order, on routes
of any proxies.

```json
{
  "routes": [{ "proxy_id": 1, "id": 12 }, { "proxy_id": 2, "id": 40 }],
  "operations": [{ "op": "disable" }, { "op": "set_group", "group": "Web app" }],
  "dry_run": false
}
```

`id` is the route's id (its router) in `GET /api/proxies/{id}/routes`; `GET /api/proxy/routes/targets`
answers the `routes` list for every route a search and filters match. The operations:

| `op` | Fields |
| --- | --- |
| `set_status` | A [status page](/api/status-pages) on every hostname of the routes: `kind`, `title`, `message`, `allow_ips`, `starts_at`, `ends_at`, `link`, `redirect_to`, `keep_path`, `permanent`, and `include_redirects` (redirect routes' hostnames too, ending their redirect) |
| `clear_status` | Their status pages go (`include_redirects`) |
| `enable`, `disable` | Turn them on or off |
| `set_group` | `group`; `""` for none |
| `set_https` | `tls`, `redirect_http` |
| `set_switch` | `name` and `on`. On or off: `waf`, `challenge`, `cache`, `waiting_room`, `uploads`, `rate_limit` (on with the route dialog's defaults; one already on keeps its settings). Off only: `allow_ips`, `headers`, `rules`, `firewall`, `basic_auth`, `sign_in` |
| `add_middleware`, `remove_middleware` | `id`: a shared middleware |
| `set_upstream` | `id`: an upstream of `/api/proxy/upstreams` |
| `serve_on` | `add`, `remove`: proxy ids |
| `delete` | `unproxy` (default `true`): the names' DNS records stop going through those proxies |

At most 100 operations and 5,000 routes. Every proxy touched is checked first; if one route can't
take an operation, the answer is `400` with every route's reason and nothing is written. Otherwise
it answers `{"applied": true, "routes", "versions", "plans", "statuses", "notes"}`: how many routes,
the [route history](/proxy/route-history) versions made, each proxy's plan, the status pages set or
cleared, and notes (such as DNZ Proxy switches left off on a Traefik or Caddy). With `"dry_run":
true` nothing is written and `applied` is `false`.

`serve_on` and `delete` are refused (`409`) in a zone whose changes wait for approval for you. TCP and
UDP routes take only `set_upstream`, `serve_on` and `delete`. It needs `proxy.manage`, and for status
pages the right to set them on the hostnames' zones. The audit log has one `proxy.routes.bulk` entry.

[Scheduled maintenance](/api/status-pages#scheduled-maintenance) (`/api/proxy/maintenance`) is with
the status pages.

## Upstreams

[Upstreams](/proxy/upstreams) are every proxy's, so they have endpoints of their own:

| Method | Path | Description |
| --- | --- | --- |
| `GET` / `POST` | `/api/proxy/upstreams` | Every upstream, with what uses it (`usage`) and `servers_now` (the servers the proxies get), or add one. A page at a time with `page` / `per_page` ([below](#a-page-of-upstreams)) |
| `GET` / `PUT` / `DELETE` | `/api/proxy/upstreams/{id}` | One upstream: show, change, delete (refused while anything uses it) |
| `POST` | `/api/proxy/upstreams/discover` | `{"protocol", "discovery"}`: looks a DNS name up now, saving nothing (the dialog's **Test**). Answers `{"resolved_by", "addresses", "servers", "ttl", "error", "left_out"}` |
| `POST` | `/api/proxy/upstreams/{id}/discover` | The same for a saved upstream; for a name each proxy looks up itself, what each DNZ Proxy node reported (`nodes`) |

An upstream whose servers come from a [DNS name](/proxy/upstream-discovery) has `discovery`:

```json
{
  "mode": "dns",
  "name": "swarm-nodes.example.local",
  "port": 8080,
  "scheme": "http",
  "family": "v4",
  "resolve_on": "dnz",
  "min_interval_secs": 30
}
```

- `scheme` (HTTP): `http` (default), `https` or `h2c`. `tls` (TCP): the servers speak TLS.
- `family`: `v4` (A, default), `v6` (AAAA) or `both`.
- `resolve_on`: `dnz` (default: DNZ looks the name up with its own DNS) or `proxy` (each DNZ Proxy node
  and Caddy look it up, for `tasks.<service>`; HTTP only, refused on Traefik).
- `min_interval_secs`: looked up again after the TTL, but not sooner than this (5 to 3,600).
- `{}` means servers listed on the upstream; a `PUT` without `discovery` keeps what it has.

`discovered` is what DNZ found: `servers`, `checked_at`, `changed_at`, `ttl`, `error`, `error_since`
(the last servers stay while lookups fail), `missing_since` (NXDOMAIN) and `left_out` (addresses of
the proxies themselves).

### A page of upstreams

`GET /api/proxy/upstreams?page=&per_page=` (50 a page, at most 200) answers
`{"upstreams": [...], "total", "page", "per_page", "counts", "twins"}`, after these filters:

| Parameter | |
| --- | --- |
| `q` | Text in the name, description, discovered DNS name, a server or a route |
| `protocol` | `http`, `tcp` or `udp` |
| `unused` | `true`: only upstreams nothing uses |
| `own` | `hide`: leave out routes' own upstreams |

`counts` (per protocol, not used, routes' own) are of every upstream, whatever the filters; `twins`
pairs upstreams with the same servers, which can be merged. Without `page` and `per_page` the answer
is every upstream, as before (the route dialogs read it that way).

## Records from Traefik's routers

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/proxies/{id}/auto-records` | `enabled`, `last_run_at`, `last_error`, `skipped` and the `hosts` found |
| `PUT` | `/api/proxies/{id}/auto-records` | `{"enabled": true}`. Needs the Traefik API; reads it right away. |
| `POST` | `/api/proxies/{id}/auto-records/sync` | Read the Traefik's routers now |
| `POST` | `/api/proxies/{id}/auto-records/hosts/{host}/release` | Keep a name's records as manual ones; DNZ makes none for it again |
| `POST` | `/api/proxies/{id}/auto-records/hosts/{host}/manage` | Manage a released name again |
| `DELETE` | `/api/proxies/{id}/auto-records/hosts/{host}` | Delete an orphaned name's records (409 while a router routes it) |

For a proxy declared with `DNZ_PROXY_SEED_*`, a `PUT /api/proxies/{id}` that changes a field in
`locked_fields`, a `DELETE`, a new token and, when `DNZ_PROXY_SEED_AUTO_RECORDS` is set, the
`auto-records` switch are refused with 400, naming the setting. For a declared DNZ Proxy,
`PUT /api/proxies/{id}/dnz/settings` with `"auto_approve": false` is refused too; `GET
/api/proxies/{id}/dnz` says so with `auto_approve_locked`.

A host has `host`, `zone_id`, `zone`, `routers`, `records` (how many DNZ keeps) and `status`:

| `status` | Meaning |
| --- | --- |
| `created` | DNZ made and keeps its records |
| `exists` | The name has records of its own |
| `no_zone` | No local primary zone holds the name |
| `orphaned` | No router routes it any more |
| `released` | Kept as manual records |

| Method | Path | Description |

## Objects

### A proxy

```json
{
  "name": "Edge A", "kind": "traefik", "ipv4": "203.0.113.10", "ipv6": "2001:db8::10",
  "traefik_api_url": "http://10.0.0.12:8080", "traefik_api_user": "", "traefik_api_password": "…"
}
```

- `kind` is `traefik`, `dnz` (DNZ Proxy) or `caddy`. It is set when the proxy is added and can't
  be changed.
- Leave `traefik_api_password` out to keep the stored one; `null` removes it.
- Add `"connects_from": "10.0.0.12"` to set the address the Traefik calls DNZ from. Leave it out to
  keep the current one, or send `null` to recognize the Traefik by `ipv4` / `ipv6` again.

Responses also carry:

| Field | Meaning |
| --- | --- |
| `status` | `pending`, `approved`, `ignored`, or `read_only` for a [read-only proxy](/api/proxy-sites) (which the endpoints here don't edit) |
| `detected_ip`, `detected_name` | How a Traefik or Caddy with the connect key is recognized |
| `has_token` | Whether the proxy has a token of its own |
| `locked_fields` | In `GET /api/settings/proxy`: the fields `DNZ_PROXY_SEED_*` sets (`name`, `kind`, `token`, `auto_approve`, `ipv4`, `traefik_api_url`, `auto_records`, …); empty for other proxies |
| `last_seen_at`, `last_seen_ip` | When and from where it last fetched its configuration |

### A router

```json
{
  "name": "app", "hosts": ["app.example.com"], "path_prefix": "", "entry_points": ["websecure"],
  "tls": true, "cert_resolver": "letsencrypt", "service_id": 1, "middlewares": [2],
  "priority": null, "enabled": true
}
```

- `matchers` are conditions such as
  `{"kind": "Header", "name": "X-Env", "values": ["prod"], "not": false}`. `kind` is `Path`,
  `PathPrefix`, `PathRegexp`, `Method`, `Header`, `HeaderRegexp`, `Query`, `QueryRegexp` or
  `ClientIP`; `name` is the header or query parameter.
- `extra_rule` is Traefik rule syntax.
- `options` holds `tls.options`, `tls.domains` and `observability`, in Traefik's shape.

### A service

```json
{
  "name": "app",
  "servers": [{ "url": "http://10.0.0.10:8080", "weight": 3 }, { "url": "http://10.0.0.11:8080", "weight": 1 }],
  "pass_host_header": true, "skip_tls_verify": true, "health_check_path": "", "health_check_interval_secs": 10,
  "strategy": "wrr", "sticky": false, "sticky_cookie": ""
}
```

- `servers` may also be plain URLs (weight 1). A server can add `"preserve_path": true`.
- `kind` is `loadBalancer` (the default), `weighted`, `mirroring` or `failover`.
- `options` hold the rest in Traefik's shape. For a load balancer: `healthCheck` (besides `path` and
  `interval`), `sticky.cookie` (besides `name`), `passiveHealthCheck` and `responseForwarding`. For
  the others, the whole service:

```json
{"kind": "failover", "options": {"service": "app", "fallback": "maintenance", "errors": {"status": ["502-504"]}}}
```

<Warning>
  Unknown fields are refused, since Traefik would reject the proxy's whole configuration over one.
</Warning>

### A middleware

```json
{ "name": "redirect-to-https", "kind": "redirectScheme", "config": { "redirectScheme": { "scheme": "https", "permanent": true } } }
```

- `kind` is its Traefik type (`redirectScheme`, `headers`, `chain`, …; the setup's `kinds` lists
  them), or `raw` for any other. `config` holds exactly that one type.
- The first kinds (`redirect_https`, `basic_auth`, `strip_prefix`, `ip_allow_list`, `rate_limit`) are
  still accepted.
- A chain's `middlewares` and an error-pages `service` are names of other middlewares and upstreams,
  which every proxy shares.
- `protocol` is `http` (the default) or `tcp`: a TCP middleware's `kind` is `ipAllowList` or
  `inFlightConn`.

### Objects: TLS, TCP and UDP

TLS, TCP and UDP routers are **objects** under `/api/proxies/{id}/objects`:
`{"kind", "name", "config"}`, with `config` in Traefik's shape.

| `kind` | Notes |
| --- | --- |
| `certificate` | `certFile`, `keyFile` as PEM |
| `tlsStore` | Only `default`: `defaultCertificate` names a certificate, or `defaultGeneratedCert` |
| `tlsOptions` | |
| `tcpRouter` | `hostSNI` and `clientIP` lists and an extra `rule`, instead of Traefik's rule |
| `tcpService` | |
| `udpRouter` | |
| `udpService` | |

`serversTransport`, `tcpServersTransport` and `tcpMiddleware` are refused since DNZ v2: transports are
an upstream's [connection settings](/proxy/upstreams#connection-settings), and TCP middlewares are in
`/api/proxy/middlewares`.

Names of other objects go as they are (`name@provider` for another provider's). Unknown fields are
refused.

The setup lists certificates without `keyFile`, with `has_key` and `info` (names, validity, issuer).

## Proxying records

On records, `proxies` puts an A, AAAA or CNAME record behind one or more proxies (`[1, 3]`); `[]` is
DNS only. Each proxy needs a router for the record's name. The bulk API's `set_proxies` moves a name's
records at once. See [Records API](/api/records#proxied-records).
