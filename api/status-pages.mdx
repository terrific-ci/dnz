---
title: "Status pages API"
description: "Endpoints for setting, scheduling and lifting the status pages of proxied hosts."
---

For what status pages do, see [Status pages](/proxy/status-pages). The endpoints take a signed-in
session or an API token (see [API overview](/api/overview)).

<Note>
  Superadmins manage every status. Others manage the statuses of hosts in zones where they have
  `records.write`, and see those of zones they can read (`zones.read`). A host in none of DNZ's zones
  is superadmin-only, so a token can't reach it.
</Note>

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/status-pages` | `{"items": [...], "kinds": [...]}`: the statuses you can see, and the statuses to choose from |
| `GET` | `/api/status-pages/hosts` | Hosts a status can be set on, with the proxies serving each |
| `GET` | `/api/status-pages/{id}` | One status |
| `POST` | `/api/status-pages` | Set a host's status (409 when it already has one) |
| `PUT` | `/api/status-pages/{id}` | Replace a status (send every field) |
| `DELETE` | `/api/status-pages/{id}` | Remove a status (204) |
| `POST` | `/api/status-pages/{id}/enable` | Turn it on |
| `POST` | `/api/status-pages/{id}/disable` | Turn it off; it is kept |
| `GET` | `/api/status-pages/preview?kind=…` | The page as visitors would see it |

## A status

The body of `POST` and `PUT`:

```json
{
  "host": "app.example.com",
  "kind": "maintenance",
  "title": "",
  "message": "We're upgrading the database. Back by 01:00.",
  "starts_at": "2026-10-25T22:00:00+07:00",
  "ends_at": "2026-10-26T01:00:00+07:00",
  "allow_ips": ["203.0.113.7", "10.0.0.0/8"],
  "link": "https://status.example.com",
  "redirect_to": "",
  "keep_path": false,
  "permanent": true,
  "enabled": true
}
```

| Field | Meaning |
| --- | --- |
| `host` | The host, e.g. `app.example.com` or `*.example.com` (one label below). A proxy must serve it |
| `kind` | `maintenance`, `coming_soon`, `unreachable`, `blocked`, `unauthorized`, `suspended`, `rate_limited`, `geo_blocked`, `moved` or `gone` |
| `title`, `message` | Instead of the usual ones (up to 120 and 2000 characters); empty for the usual ones |
| `starts_at`, `ends_at` | RFC 3339, or `null`. Stored in UTC; `ends_at` can't be in the past |
| `allow_ips` | IPs and CIDRs that reach the backend as usual (up to 100) |
| `link` | The *More information* button (`http://` or `https://`) |
| `redirect_to` | `moved`: the new address (required for it) |
| `keep_path` | `moved`: keep the path and query |
| `permanent` | `moved`: `true` (the default) answers 301, which browsers remember; `false` a temporary 302. The status's `code` says which |
| `enabled` | Default `true` |

Answers add `id`, `zone_id`, `zone`, `state` (`active`, `scheduled`, `ended` or `off`), `code`,
`label`, `retry_after` (seconds right now, or `null`), `proxies` (`[{"id", "name"}]`, the proxies
serving the host), `updated_by`, `created_at` and `updated_at`.

`GET /api/status-pages/hosts` answers `{"items": [{"host", "zone_id", "zone", "proxies"}]}`. Each
entry of `kinds` has `kind`, `label`, `code`, `title` and `message` (`{host}` is filled in on the
page).

## Example

```bash
curl -X POST https://dns.example.com/api/status-pages \
  -H "Authorization: Bearer $DNZ_TOKEN" -H "Content-Type: application/json" \
  -d '{"host":"app.example.com","kind":"maintenance","ends_at":"2026-10-26T01:00:00+07:00",
       "allow_ips":["203.0.113.7"],"link":"https://status.example.com"}'
```

## Several routes at once

To set or clear the status of every hostname of several routes, on every proxy serving them, in one
request, use `POST /api/proxy/routes/bulk` with a `set_status` or `clear_status` operation (see
[Several routes at once](/api/proxy#several-routes-at-once)). It takes the fields above, plus
`include_redirects`; nothing changes unless every hostname takes it. It also needs `proxy.manage`.

## Scheduled maintenance

[Scheduled maintenance](/proxy/status-pages#scheduled-maintenance) that repeats has endpoints of its
own. They need `proxy.manage` and the right to set status pages on the hostnames' zones.

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/proxy/maintenance` | `{"windows": [...], "timezone"}`: every window, each with `active` (on now), `next_start` and `next_end` (its current or next occurrence, `null` when none is left) and `not_served` (hostnames no proxy serves); `timezone` is the server's |
| `GET` | `/api/proxy/maintenance/upcoming?days=7` | `{"days", "occurrences": [{"id", "name", "hosts", "starts_at", "ends_at", "on_public_page"}]}`: the occurrences of the next 1 to 31 days, earliest first |
| `GET` | `/api/proxy/maintenance/{id}` | One window |
| `POST` | `/api/proxy/maintenance` | Add one (201; 409 when the name is taken) |
| `PUT` | `/api/proxy/maintenance/{id}` | Change one (send every field) |
| `DELETE` | `/api/proxy/maintenance/{id}` | Delete one (204) |

```json
{
  "name": "Weekly backups",
  "hosts": ["app.example.com", "api.example.com"],
  "days": 64,
  "start_minute": 1320,
  "duration_mins": 120,
  "starts_on": null,
  "ends_on": null,
  "title": "",
  "message": "Weekly backups. Back by midnight.",
  "allow_ips": [],
  "quiet_alerts": true,
  "on_public_page": true,
  "enabled": true
}
```

| Field | Meaning |
| --- | --- |
| `name` | Unique |
| `hosts` | The hostnames it covers; `*.example.com` covers one label below |
| `days` | Bits: 1 = Monday, 2 = Tuesday … 64 = Sunday; 31 is Monday to Friday, 127 every day |
| `start_minute` | Minutes after midnight **in the server's time zone** (1320 = 22:00) |
| `duration_mins` | From 1 minute to a week (10080); it may run past midnight |
| `starts_on`, `ends_on` | `YYYY-MM-DD` in the server's time zone, or `null` |
| `title`, `message`, `allow_ips` | As for a status above; empty for the maintenance page's usual ones |
| `quiet_alerts` | Uptime monitors of the hostnames stay quiet during it (default `true`) |
| `on_public_page` | Its occurrences show on the public status page (default `true`) |
| `enabled` | Default `true` |

The audit log has `proxy.maintenance.create`, `.update` and `.delete`.

## Preview

`GET /api/status-pages/preview` renders the page with `kind` and, optionally, `host`, `title`,
`message`, `link`, `redirect_to`, `permanent`, `ends_at` and `proxy`. It answers HTML, JSON or text by `Accept`,
like the proxy does.

## Errors

Errors come back as `{"error": "…"}`: `400` for a name no proxy serves or a field that doesn't check
out, `403` without the permission, `404` for a status you can't see, `409` when the host already has
a status.
