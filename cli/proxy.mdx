`dnz proxy` covers turning proxying on or off, adding **proxies** (Traefik, dnz-proxy or Caddy),
adding a **route** (one hostname through a proxy) and managing the **nodes** of DNZ's own reverse
proxy, dnz-proxy. All `dnz proxy` commands need a superadmin.

For the concepts, see [Proxy overview](/proxy/overview), [Routing](/proxy/routing) and
[dnz-proxy](/proxy/dnz-proxy).

## Proxying and proxies

```bash
dnz proxy show                                    # proxying on/off, proxies, connect key
dnz proxy on                                      # or: dnz proxy off
dnz proxy add edge-1 --ipv4 203.0.113.10          # a Traefik (the default kind)
dnz proxy add edge-2 --kind caddy --ipv4 203.0.113.20 --connects-from 10.0.0.20
dnz proxy add "Edge JKT" --kind dnz --ipv4 203.0.113.30   # dnz-proxy nodes join it
dnz proxy caddy edge-2                            # what the Caddy is sent, and what it can't take
```

`on` and `off` match the switch under **Settings → Proxy**; with `DNZ_PROXY_BACKEND` set, `show` says
so and the switch can't change. With `DNZ_PROXY_CONNECT_KEY` set, `show` says so after the connect key.
A proxy declared with `DNZ_PROXY_SEED_*` shows **environment** under
**SET BY**: the fields set there can't be changed, and it can't be deleted or get another token (see
[DNZ and Traefik in one compose file](/proxy/compose)). `add` takes:

| Option | What it does |
| --- | --- |
| `--kind` | What runs it: `traefik` (default), `dnz` (or `dnz-proxy`) or `caddy`. Can't change later |
| `--ipv4`, `--ipv6` | Where visitors reach it; DNS answers with these. At least one |
| `--connects-from` | The address a Traefik or Caddy calls DNZ from, when it isn't one of the above |

See [Connecting Traefik](/proxy/traefik), [Connecting Caddy](/proxy/caddy) and
[dnz-proxy](/proxy/dnz-proxy).

## Records from Traefik's routers

What a proxy's **From Traefik** tab does: DNS records for the hostnames of the Traefik's own routers
(Docker labels, Swarm, Kubernetes, files, …). See [Records from Traefik's routers](/proxy/traefik-records).
`auto` is short for `auto-records`.

```bash
dnz proxy auto-records show edge                  # on/off, the last read, every hostname and what DNZ did with it
dnz proxy auto-records on edge                    # turn it on (needs the proxy's Traefik API) and read Traefik now
dnz proxy auto-records off edge                   # turn it off; the records made so far stay
dnz proxy auto sync edge                          # read Traefik now instead of within 30 seconds
dnz proxy auto zones edge                         # zones the routers' hostnames need that DNZ doesn't have
dnz proxy auto zones edge --create -d default     # make them in a division and turn it on
dnz proxy auto release edge app.example.com       # stop managing a name; its records stay as manual ones
dnz proxy auto manage edge app.example.com        # manage a released name again
dnz proxy auto forget edge old.example.com        # delete an orphaned name and the records DNZ made for it
```

In `show`, **STATUS** is `created`, `exists`, `no_zone`, `orphaned` or `released` (see
[What DNZ leaves alone](/proxy/traefik-records#what-dnz-leaves-alone)). Routers whose rule has no
hostname DNS can answer are listed below it, with the reason. `on` and `off` are refused when
`DNZ_PROXY_SEED_AUTO_RECORDS` sets it.

## Proxy routes

`dnz proxy routes` does what **Routes** on a proxy's page does: one hostname (or a few) through a
proxy, with its service, router(s), the switches' middlewares and DNS record kept together.
`dnz proxy route …` is the same as `dnz proxy routes add …`.

### Find a hostname

```bash
dnz proxy hosts edge                              # names with A/AAAA/CNAME records, and whether edge routes them
dnz proxy hosts edge portal                       # what Add route offers for "portal": existing names, and new ones per zone
```

The first argument is the proxy, by name or id. In the output, **DNS** shows a name's record types, or
**new** when the name has no record yet.

### List, add, edit, delete

```bash
dnz proxy routes list edge                        # hostnames, where they go, HTTPS / certificate, switches
dnz proxy routes add edge app.example.com -u http://10.0.1.20:3000
dnz proxy routes add edge app.example.com -u http://10.0.1.20:3000=3 -u http://10.0.1.21:3000 \
  --also www.example.com --cache 10m --user admin:s3cret --allow 10.0.0.0/8
dnz proxy routes add edge api.example.com -u http://10.0.2.11:8080 --rate-limit 100/300 --firewall office
dnz proxy routes add edge intranet.example.com -u http://10.0.9.4 --http        # HTTP only
dnz proxy routes add edge shop.example.com --service shop                       # to one of edge's services
dnz proxy routes edit edge app.example.com --no-cache --user ops:other-pass --remove-user admin
dnz proxy routes edit edge app.example.com --https off
dnz proxy routes cert edge app.example.com        # the certificate's state and latest steps; --renew gets it again
dnz proxy routes clear-cache edge app.example.com
dnz proxy routes rm edge app.example.com          # its DNS records stop going through edge
```

What happens to DNS:

- A name with no record yet gets an A (or AAAA) record pointing at the proxy.
- A name that already has records keeps them, now proxied.
- With `--no-dns`, DNS is left alone: no new record, and existing ones are not proxied.

The hostname must be in one of DNZ's zones; `*.example.com` covers one label. A hostname outside
every zone, or one the proxy already routes, is refused, and the closest names are offered.

| Option (`add`) | What it does |
| --- | --- |
| `-u`, `--upstream` | Upstream URL with scheme and port; repeat for more. Append `=WEIGHT` to share visits unevenly, e.g. `http://10.0.0.10:8080=3`. Required unless `--service` |
| `--service` | Send the visits to one of the proxy's services instead, by name or id. The route uses it as it is, and deleting the route leaves it |
| `--also` | Another hostname of the same route; repeat for more |
| `--http` | Plain HTTP only: no HTTPS router and no redirect |
| `--no-redirect` | Keep `http://` as it is instead of redirecting to `https://` |
| `--cert-resolver` | Certificate resolver for HTTPS; default: DNZ's automatic certificates on dnz-proxy |
| `--path` | Only paths under this, e.g. `/api` |
| `--cache [TTL]` | Cache answers on the nodes (dnz-proxy), default `10m` |
| `--firewall` | Run one of the proxy's firewall middlewares first (dnz-proxy) |
| `--challenge` | The "under attack" browser check (dnz-proxy) |
| `--waiting-room` | A waiting room letting this many visitors in at once (dnz-proxy); `--queue-all` makes everyone wait |
| `--rate-limit` | Requests a second per visitor, optionally with a burst: `100` or `100/300` |
| `--user` | `NAME:PASSWORD` for a password; repeat for more. Only a bcrypt hash is kept |
| `--allow` | Only these addresses or ranges get through; repeat for more |
| `--request-header` | `NAME=VALUE` set on requests to the upstreams; `NAME=` removes the header; repeat for more |
| `--response-header` | `NAME=VALUE` set on answers to visitors; `NAME=` removes the header; repeat for more |
| `-m`, `--middleware` | Another middleware by name or id, in order; repeat for more |
| `--no-dns` | Leave the DNS record alone |
| `--strategy` | How the upstreams share visits: `wrr` (default), `p2c`, `hrw` or `leasttime` |
| `--sticky` | Keep each visitor on the upstream it first reached (a cookie) |
| `--http-entry` | Entry point for `http://` |
| `--https-entry` | Entry point for `https://` |

`routes edit` changes only what you pass: `--add-host`, `--remove-host`, `-u` (replacing the
upstreams, or giving a route on a service upstreams of its own), `--service NAME` (one of the
proxy's services instead), `--https on|off`, `--redirect on|off`, `--path`, `--enabled on|off`, the switches above,
and `--no-cache`, `--no-firewall`, `--no-challenge`, `--no-waiting-room`, `--no-rate-limit`, `--no-password`,
`--remove-user NAME`, `--no-allow`, `--drop-request-header NAME`, `--drop-response-header NAME`,
`--no-headers`. A route set up under **Advanced** is refused with the reason.

```bash
dnz proxy routes edit edge app.example.com --request-header X-Env=production --response-header Server=
```

HTTPS with a redirect from `http://` is the default. On a dnz-proxy proxy its certificate comes by
itself once [automatic certificates](#certificates) are set up; until then it gets a temporary one.

### Entry points

The server picks the entry points, the same ones the dashboard's **Add route** uses:

- under **dnz-proxy**, the proxy's own HTTP and HTTPS entry points;
- under **Traefik**, the ones its API lists, when the proxy has **Traefik API** set;
- under **Caddy**, `web` (:80) and `websecure` (:443).

The one on port 80 serves `http://` and the one on 443 serves `https://`; the command prints which it
picked. Without either, or when no entry point is on that port, it uses `web` and `websecure`.
`--http-entry` and `--https-entry` name them yourself.

### Route defaults (dnz-proxy)

What every route of a dnz-proxy proxy gets, live on its nodes:

```bash
dnz proxy defaults edge                           # show them
dnz proxy defaults edge --redirect-https on --compress on --security-headers on --firewall office
dnz proxy defaults edge --firewall none
```

See [Route defaults](/proxy/dnz-proxy#route-defaults).

### Certificates

DNZ's automatic certificates for dnz-proxy routes:

```bash
dnz proxy certs show                              # on or not, the account, the credentials in use
dnz proxy certs setup --agree --email admin@example.com   # once: a Let's Encrypt account (accepting its agreement)
dnz proxy certs setup --account "Let's Encrypt"   # or one DNZ already has
dnz proxy certs check edge app.example.com shop.example.org
dnz proxy certs credential shop.example.org --cloudflare-token …
dnz proxy certs credential shop.example.org --rfc2136 192.0.2.53:53 --key-name acme. --secret …
dnz proxy certs credential shop.example.org --webhook https://hooks.example.com/acme --suffix example.org
```

`certs check` says per name how DNZ would prove it: DNZ's own zone, a Cloudflare connection, a DNS
credential, HTTP-01 through the nodes, or **needs a way**. `certs credential` adds and removes a test
TXT record first and keeps the credential only when that works. `DNZ_CLOUDFLARE_TOKEN` and
`DNZ_ACME_SECRET` keep secrets off the command line. See
[Automatic certificates](/proxy/certificates#automatic-certificates).

## dnz-proxy nodes

```bash
dnz proxy nodes                                   # every node: proxy, state, addresses, config
dnz proxy approve jkt-1 --proxy "Edge JKT" --ipv4 203.0.113.10
dnz proxy ignore node-10-0-0-9                    # turn a waiting node away
dnz proxy drain jkt-1                             # out of DNS answers, still serving
dnz proxy drain jkt-1 --undo
dnz proxy remove jkt-1                            # it can't connect any more
```

`dnz proxy show` prints whether proxying is on, the proxies and the **connect key** new nodes join
with. New nodes wait for approval; they can only join dnz-proxy proxies. `approve` takes:

| Option | What it does |
| --- | --- |
| `-p`, `--proxy` | The proxy it serves, by name or id. Required |
| `--ipv4`, `--ipv6` | Where visitors reach it; DNS answers with these (default: what the node asked for) |
| `--name` | A new name for the node |

Nodes are named by name or id.

### Clearing the cache

`dnz proxy purge` (or `dnz proxy clear-cache`) clears cached answers on every node of a proxy;
`dnz proxy routes clear-cache` does it for one route's hostnames:

```bash
dnz proxy purge "Edge JKT"                        # every cached answer
dnz proxy purge "Edge JKT" --host app.example.com --prefix /assets
dnz proxy purge "Edge JKT" --url https://app.example.com/logo.png
```

`--prefix` needs `--host`.

### Traffic and request logs

Each node keeps its own analytics. These commands ask the nodes, like **Proxy → Analytics**, and
say on stderr which nodes didn't answer.

```bash
dnz proxy analytics                               # last 24 h, every proxy: totals, most requested URLs, top lists
dnz proxy analytics -p "Edge JKT" --since 7d      # 1h, 6h, 24h, 7d or 30d
dnz proxy analytics --host app.example.com -n 50  # that hostname's 50 busiest paths
dnz proxy logs                                    # newest 50 request log lines
dnz proxy logs --host app.example.com --status 5xx -q /api
dnz proxy logs --client 198.51.100.7 -n 200
dnz proxy logs -f                                 # follow, oldest first (with --json: one JSON line each)
```

### Waiting rooms

A waiting room is a `dnzWaitingRoom` middleware (see
[Waiting room](/proxy/dnz-proxy#waiting-room-dnzwaitingroom)). `set` adds one or changes the settings
you give, keeping the rest. Put it on a route with `dnz proxy route … -m <name>` or in the proxy's
page.

```bash
dnz proxy waiting-room set "Edge JKT" sale-line --max-active 500 --session 5m \
  --bypass-path /api/ --bypass-path /static/ --allow-user-agent UptimeRobot
dnz proxy waiting-room set "Edge JKT" sale-line --queue-all   # before the launch: everyone waits
dnz proxy waiting-room set "Edge JKT" sale-line --open        # open: the line goes in first
dnz proxy waiting-room set "Edge JKT" sale-line --redis redis:6379   # one line across all nodes
dnz proxy waiting-room show                       # visitors in, the limit and waiting, per hostname
dnz proxy wr ls -p "Edge JKT" --json
```
