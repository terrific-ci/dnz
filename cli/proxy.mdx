`dnz proxy` covers turning proxying on or off, adding **proxies** (Traefik, DNZ Proxy or Caddy),
adding a **route** (one hostname through a proxy) and managing the **nodes** of DNZ's own reverse
proxy, DNZ Proxy. All `dnz proxy` commands need a superadmin, except
[`dnz proxy sites`](/cli/proxy-sites#permissions) for read-only proxies.

For the concepts, see [Proxy overview](/proxy/overview), [Routing](/proxy/routing) and
[DNZ Proxy](/proxy/dnz-proxy).

## Proxying and proxies

```bash
dnz proxy show                                    # proxying on/off, proxies, connect key
dnz proxy on                                      # or: dnz proxy off
dnz proxy add edge-1 --ipv4 203.0.113.10          # a Traefik (the default kind)
dnz proxy add edge-2 --kind caddy --ipv4 203.0.113.20 --connects-from 10.0.0.20
dnz proxy add "Edge JKT" --kind dnz --ipv4 203.0.113.30   # DNZ Proxy nodes join it
dnz proxy add office --ipv4 10.20.0.5             # private: every address is (--access private|public says so)
dnz proxy edit edge-1 --access private            # reached only from inside the network (LAN, VPN)
dnz proxy edit edge-1 --name edge-jkt --ipv6 ""   # only what you pass changes; "" clears an address
dnz proxy caddy edge-2                            # what the Caddy is sent, and what it can't take
dnz proxy add edge-3 --kind caddy --read-only --api http://10.0.0.5:2020 --user dnz --password --address 203.0.113.5
```

`on` and `off` match the switch under **Settings → Proxy**; with `DNZ_PROXY_BACKEND` set, `show` says
so and the switch can't change. With `DNZ_PROXY_CONNECT_KEY` set, `show` says so after the connect key.
A proxy declared with `DNZ_PROXY_SEED_*` shows **environment** under
**SET BY**: the fields set there can't be changed, and it can't be deleted or get another token (see
[DNZ and Traefik in one compose file](/proxy/compose)). `add` takes:

| Option | What it does |
| --- | --- |
| `--kind` | What runs it: `traefik` (default), `dnz` (or `dnz-proxy`) or `caddy`. Can't change later |
| `--ipv4`, `--ipv6` | Where visitors reach it; DNS answers with these. At least one |
| `--connects-from` | The address a Traefik or Caddy calls DNZ from, when it isn't one of the above |
| `--access` | `private` (reached only from inside your network: a LAN, a VPN) or `public` (from the internet). Left out: private when every address is private, else public. See [Private and public proxies](/proxy/overview#private-and-public-proxies) |
| `--read-only` | A Caddy or Traefik that keeps its own configuration: DNZ never configures it, it reads its sites from `--api` and keeps DNS records for them. Takes the flags of [`dnz proxy sites add`](/cli/proxy-sites#adding) (`--ipv4` / `--ipv6` count as addresses), `--division` and `--paused` |

`show` lists each proxy's **ACCESS**. `dnz proxy edit PROXY` changes a proxy DNZ configures (a
read-only one is [`dnz proxy sites edit`](/cli/proxy-sites)): `--name`, `--ipv4`, `--ipv6` and
`--access`; only what you pass changes.

See [Connecting Traefik](/proxy/traefik), [Connecting Caddy](/proxy/caddy),
[Read-only proxies](/proxy/read-only) and [DNZ Proxy](/proxy/dnz-proxy). Read-only proxies are
listed, previewed, synced, paused and removed with [`dnz proxy sites`](/cli/proxy-sites).

## Records from Traefik's routers

What a proxy's **From Traefik** tab does: DNS records for the hostnames of the Traefik's own routers
(Docker labels, Swarm, Kubernetes, files, …). See [Records from Traefik's routers](/proxy/traefik-records).
`auto` is short for `auto-records`.

```bash
dnz proxy auto-records show edge                  # on/off, the last read, every hostname and what DNZ did with it
dnz proxy auto-records on edge                    # turn it on (needs the proxy's Traefik API) and read Traefik now
dnz proxy auto-records off edge                   # turn it off; the records made so far stay
dnz proxy auto sync edge                          # read Traefik now instead of within 30 seconds
dnz proxy auto zones edge                         # zones the routers' hostnames need that DNZ doesn't have
dnz proxy auto zones edge --create -d default     # make them in a division and turn it on
dnz proxy auto release edge app.example.com       # stop managing a name; its records stay as manual ones
dnz proxy auto manage edge app.example.com        # manage a released name again
dnz proxy auto forget edge old.example.com        # delete an orphaned name and the records DNZ made for it
```

In `show`, **STATUS** is `created`, `exists`, `no_zone`, `orphaned` or `released` (see
[What DNZ leaves alone](/proxy/traefik-records#what-dnz-leaves-alone)). Routers whose rule has no
hostname DNS can answer are listed below it, with the reason. `on` and `off` are refused when
`DNZ_PROXY_SEED_AUTO_RECORDS` sets it.

## Proxy routes

`dnz proxy routes` does what **Routes** on a proxy's page does: one hostname (or a few) through a
proxy, with its service, router(s), the switches' middlewares and DNS record kept together.
`dnz proxy route …` is the same as `dnz proxy routes add …`.

### Find a hostname

```bash
dnz proxy hosts edge                              # names with A/AAAA/CNAME records, and whether edge routes them
dnz proxy hosts edge portal                       # what Add route offers for "portal": existing names, and new ones per zone
```

The first argument is the proxy, by name or id. In the output, **DNS** shows a name's record types, or
**new** when the name has no record yet.

### List, add, edit, delete

```bash
dnz proxy routes list                             # every proxy's routes, one row per hostname: PROXIES, where they go
                                                  # (→ ADDRESS for a redirect), HTTPS (tcp/udp for TCP and UDP routes), switches
dnz proxy routes list edge                        # one proxy's (edge office, or edge,office: several proxies')
dnz proxy routes list --page 2 --limit 100        # 20 a page by default (at most 200); the footer says "51-100 of 1240 routes"
dnz proxy routes list --by-zone                   # under the zone of each hostname (no zone last)
dnz proxy routes list --search shop               # only routes whose hostname (or path, upstream, group, proxy) contains it
dnz proxy routes list --by-group                  # under each route's group (no group last)
dnz proxy routes list --group "Web app"           # one group's routes (--group - : those in none)
dnz proxy routes list --group "Web app" --group - # several groups: routes in any of them
dnz proxy routes list --zone example.com          # one zone's routes (--zone - : those in none)
dnz proxy routes list edge --visitors             # plus VISITORS (24H): distinct visitors and a line per hour (DNZ Proxy)
dnz proxy routes list --type redirect             # one type: on, off, redirect, https, http, tcp, udp, cert-failing, dns-missing,
                                                  # advanced, or a switch (cache, firewall, waf, under-attack, waiting-room,
                                                  # rate-limit, password, sign-in, allow, headers, uploads, rules)
dnz proxy routes list --type http,tcp             # several types (or --type http --type tcp): routes of any of them
dnz proxy routes list --access private            # only the private proxies' routes (--access public: the public ones')
dnz proxy routes add edge app.example.com -u http://10.0.1.20:3000
dnz proxy routes add office intranet.example.com -u http://10.0.9.4 --serve-on private   # on every private proxy too
dnz proxy routes add edge app.example.com -u http://10.0.1.20:3000=3 -u http://10.0.1.21:3000 \
  --also www.example.com --cache 10m --user admin:s3cret --allow 10.0.0.0/8
dnz proxy routes add edge api.example.com -u http://10.0.2.11:8080 --rate-limit 100/300 --firewall office
dnz proxy routes add edge intranet.example.com -u http://10.0.9.4 --http        # HTTP only
dnz proxy routes add edge shop.example.com --service shop                       # to an upstream of Proxy → Upstreams
dnz proxy routes add-tcp edge -e pg --host db.example.com --passthrough -t 10.0.0.7:5432   # TCP by hostname (SNI)
dnz proxy routes add-tcp edge -e pg -t 10.0.0.7:5432 --middleware office-only  # with a TCP middleware (repeat -m for more)
dnz proxy routes add-udp edge -e dns --service resolvers                        # UDP to a shared upstream
dnz proxy routes add edge old.example.com --redirect-to https://new.example.com --keep-path   # a redirect, no upstream
dnz proxy routes edit edge app.example.com --no-cache --user ops:other-pass --remove-user admin
dnz proxy routes edit edge app.example.com --https off
dnz proxy routes add edge app.example.com -u http://10.0.1.20:3000 -u http://10.0.1.21:3000?health=/status \
  --health-check /healthz --health-interval 15                                  # its servers' health check
dnz proxy routes edit edge app.example.com --health-check /ready                # `none` stops the checks
dnz proxy routes cert edge app.example.com        # the certificate's state and latest steps; --renew gets it again
dnz proxy routes clear-cache edge app.example.com
dnz proxy routes rm edge app.example.com          # its DNS records stop going through edge
```

`--serve-on private|public|all` saves the route on every other approved proxy of that access too,
one after the other as the route dialog's **Serve on** does (one that fails is reported and the rest
go on). It picks the proxies as they are now: a proxy added later doesn't get the route.

`--health-check PATH` and `--health-interval SECONDS` (default 10) are the health check of a route's
own servers, as the route dialog's **Health check**: each server is asked for the path and gets no
visits while it fails. A server's own path goes after its `--upstream` as `?health=PATH` (or
`?health=off`), DNZ Proxy only. `routes edit` changes only what it names; a route on a shared upstream
is refused with the `dnz proxy upstreams edit NAME --health-check PATH` that sets it for every route
using it. `dnz record add|edit --upstream` takes the same two flags.

`routes list` is Proxy → Routes in the terminal. The proxy is optional (one or several): without it (or with `all`),
every proxy's routes are listed, one row per hostname, and the **PROXIES** column names the proxies
serving it. The server searches, filters and pages before a page is cut, so the footer counts every
route that matches; with `--by-zone` or `--by-group` a zone or group can run on over several pages.
`--json` prints the server's answer: `rows`, each with its `hosts`, `zone`, `group` and `entries` (one
per proxy, with that proxy's copy of the route), plus `total`, `page` and `per_page`
([Proxy API](/api/proxy#the-routes-page)).

### History and restore

Every add, edit, delete and group move of a route is kept as a version ([Route history](/proxy/route-history)).

```bash
dnz proxy routes history edge                     # every change to edge's routes, newest first (deleted ones too)
dnz proxy routes history edge app.example.com     # one hostname's route; --page 2 for older, --limit 100
dnz proxy routes history edge app.example.com 7   # what version 7 changed, part by part
dnz proxy routes restore edge app.example.com 7   # the route as it was right after version 7 (asks first; -y)
dnz settings route-history --keep-days 365 --keep-versions 1000   # how long versions are kept (superadmin)
```

Restoring a *Deleted* version makes the route again. A restore is kept as a new version, and never
takes a DNS record off the proxy.

### Route groups

Groups (*Web app*, *REST API*, …) only sort the Routes page; no proxy's configuration changes.
`add` and `edit` also take `--group NAME` (`edit --no-group` takes it out).

```bash
dnz proxy routes group app.example.com "Web app"  # on every proxy serving it (--proxy: only one)
dnz proxy routes group app.example.com --none     # out of its group
dnz proxy routes groups                           # every group (empty ones too), with their routes
dnz proxy routes groups add "REST API"            # a group with no routes yet
dnz proxy routes groups rename "Web app" Apps     # on every proxy; another group's name merges the two
dnz proxy routes groups rm Apps                   # its routes stay, in no group
```

What happens to DNS:

- A name with no record yet gets an A (or AAAA) record pointing at the proxy.
- A name that already has records keeps them, now proxied.
- With `--no-dns`, DNS is left alone: no new record, and existing ones are not proxied.

The hostname must be in one of DNZ's zones; `*.example.com` covers one label. A hostname outside
every zone, or one the proxy already routes, is refused, and the closest names are offered.

| Option (`add`) | What it does |
| --- | --- |
| `-u`, `--upstream` | Upstream URL with scheme and port; repeat for more. Append `=WEIGHT` to share visits unevenly, e.g. `http://10.0.0.10:8080=3`; `https+insecure://HOST:PORT` accepts any certificate from that server. Required unless `--service` or `--redirect-to` |
| `--service` | Send the visits to an upstream of Proxy → Upstreams instead, by name or id. The route uses it as it is, and deleting the route leaves it |
| `--redirect-to` | Redirect every visit to this address instead of upstreams (a [redirect route](/proxy/overview#redirect-routes)) |
| `--keep-path` | With `--redirect-to`: keep the path and query (`/a?b` → `<URL>/a?b`) |
| `--temporary` | With `--redirect-to`: a temporary 302 instead of a permanent 301 |
| `--also` | Another hostname of the same route; repeat for more |
| `--http` | Plain HTTP only: no HTTPS router and no redirect |
| `--no-redirect` | Keep `http://` as it is instead of redirecting to `https://` |
| `--cert-resolver` | Certificate resolver for HTTPS; default: DNZ's automatic certificates on DNZ Proxy |
| `--path` | Only paths under this, e.g. `/api` |
| `--cache [TTL]` | Cache answers on the nodes (DNZ Proxy), default `10m` |
| `--firewall` | Run one of the firewalls (Proxy → Middlewares, shared by every proxy) first (DNZ Proxy) |
| `--waf` | The [web application firewall](/proxy/waf) (DNZ Proxy): `block` or `log` (only log). See [below](#web-application-firewall) for its other flags |
| `--challenge` | The "under attack" browser check (DNZ Proxy) |
| `--challenge-allow-ip CIDR`, `--challenge-allow-agent USER_AGENT` | What the check lets through, each repeatable: addresses or ranges, and user agents (crawlers and monitors without JavaScript). Each one given replaces that list (`none` empties it), the other stays; either turns the check on. One route at a time |
| `--waiting-room` | A waiting room letting this many visitors in at once (DNZ Proxy); `--queue-all` makes everyone wait |
| `--rate-limit` | Requests a second per visitor, optionally with a burst: `100` or `100/300` |
| `--user` | `NAME:PASSWORD` for a password; repeat for more. Only a bcrypt hash is kept |
| `--allow` | Only these addresses or ranges get through; repeat for more |
| `--request-header` | `NAME=VALUE` set on requests to the upstreams; `NAME=` removes the header; repeat for more |
| `--response-header` | `NAME=VALUE` set on answers to visitors; `NAME=` removes the header; repeat for more |
| `-m`, `--middleware` | Another middleware by name or id, in order; repeat for more |
| `--no-dns` | Leave the DNS record alone |
| `--strategy` | How the upstreams share visits: `wrr` (default), `p2c`, `hrw` or `leasttime` |
| `--sticky` | Keep each visitor on the upstream it first reached (a cookie) |
| `--http-entry` | Entry point for `http://` |
| `--https-entry` | Entry point for `https://` |

`routes edit` changes only what you pass: `--add-host`, `--remove-host`, `-u` (replacing the
servers, or giving a route on a shared upstream servers of its own), `--service NAME` (an
upstream of the list instead), `--https on|off`, `--redirect on|off`, `--path`, `--enabled on|off`, the switches above,
and `--no-cache`, `--no-firewall`, `--waf off`, `--no-challenge`, `--no-waiting-room`, `--no-rate-limit`, `--no-password`,
`--remove-user NAME`, `--no-allow`, `--drop-request-header NAME`, `--drop-response-header NAME`,
`--no-headers`. A route set up under **Advanced** is refused with the reason.

```bash
dnz proxy routes edit edge app.example.com --request-header X-Env=production --response-header Server=
```

HTTPS with a redirect from `http://` is the default. On a DNZ Proxy its certificate comes by
itself once [automatic certificates](#certificates) are set up; until then it gets a temporary one.

<Note>
  In a zone whose changes [wait for approval](/dns/history#change-approval), `routes add` is refused
  unless it leaves DNS alone (`--no-dns`): a route with its DNS record would change the name's
  records at once, past the approval.
</Note>

### Several routes at once

What the Routes page's bar does ([Several routes at once](/proxy/overview#several-routes-at-once)):
give `routes edit` or `routes rm` more hostnames, or `all` instead of the proxy to take each route
on **every proxy serving it**. It is one request, all or nothing: if one route can't take the
change, nothing changes, and the command prints each route's reason.

```bash
dnz proxy routes edit all app.example.com api.example.com --enabled off
dnz proxy routes edit all app.example.com api.example.com --group "Web app" --https on
dnz proxy routes edit edge app.example.com api.example.com --switch waf=on --switch cache=off
dnz proxy routes edit all app.example.com api.example.com --middleware +strip-api --middleware -old-headers
dnz proxy routes edit all app.example.com api.example.com --service web       # one shared upstream
dnz proxy routes edit edge app.example.com api.example.com --serve-on +edge2   # copy them to edge2; -edge2 takes them off
dnz proxy routes edit all app.example.com --serve-on +public                    # onto every public proxy (now)
dnz proxy routes rm all app.example.com api.example.com                         # asks first; -y
```

A batch takes:

| Flag | What it does |
| --- | --- |
| `--enabled on\|off` | Turn the routes on or off |
| `--group NAME`, `--no-group` | Put them in a [route group](#route-groups), or in none |
| `--https on\|off`, `--redirect on\|off` | HTTPS, and whether `http://` redirects to it |
| `--switch NAME=on\|off` | On, with the route dialog's defaults: `waf`, `challenge`, `cache`, `waiting_room`, `uploads`, `rate_limit`. Off also: `allow_ips`, `headers`, `rules`, `firewall`, `basic_auth`, `sign_in`. Repeat for more; a switch already on keeps its settings |
| `--challenge`, `--cache`, `--waf block\|off`, the `--no-…` switches | The same as `--switch`. `--cache` only at its default of 10 minutes (`--cache` or `--cache 10m`); a route whose cache is already on keeps its time |
| `--uploads` | The default [upload limits](/proxy/upload-limits) (`--no-uploads` turns them off) |
| `--shield ID` | A [shield](/proxy/shields) on them; `--shield -ID` takes it off, `--shield off` takes every one off; repeat for more |
| `--middleware +NAME\|-NAME` | Add or remove a shared middleware; repeat for more |
| `--service NAME` | Send them all to one upstream of Proxy → Upstreams |
| `--serve-on +PROXY\|-PROXY` | Copy the routes to another proxy, or take them off one. `+private`, `+public`, `+all` (or with `-`): every approved proxy of that access now; a proxy named so is named by its id |

Flags that carry a route's own values (servers, hostnames, users, sign-in and who may sign in,
headers, a cache time other than 10 minutes, upload limits such as `--upload-max`, WAF lists and
sensitivity, rate limit and waiting room numbers, `--waf log`) change one route on one proxy. A
batch refuses them and says why; run them without more hostnames or `all`
(`dnz proxy routes edit edge app.example.com --cache 1h`). TCP and UDP routes take only `--service`, `--serve-on` and
`rm`. In a zone whose changes wait for approval, `--serve-on` and `rm` are refused, since they
change the names' DNS records at once.

To set a status page on several routes, see
[`dnz status-page set … --also`](/cli/status-pages#several-routes-at-once); for maintenance that
repeats, [`dnz proxy maintenance`](/cli/status-pages#scheduled-maintenance).

### Web application firewall

Ready-made rules against SQL injection, XSS, path traversal, Log4Shell, attack tools and the like, on
a DNZ Proxy route. See [Web application firewall](/proxy/waf).

```bash
dnz proxy waf rules                               # every rule: id, category, the lowest sensitivity that runs it, what it catches
dnz proxy waf rules --sensitivity low             # only the rules Low runs
dnz proxy routes add edge app.example.com -u http://10.0.1.20:3000 --waf log --waf-sensitivity high
dnz proxy routes edit edge app.example.com --waf block                    # from log only to blocking
dnz proxy routes edit edge app.example.com --waf-skip-rule xss-tags --waf-skip-path /admin/editor
dnz proxy routes edit edge app.example.com --waf-allow 10.0.0.0/8         # never check the office
dnz proxy routes edit edge app.example.com --waf off
dnz proxy routes waf-hits                         # matches since the nodes started, per proxy, rule and action
dnz proxy routes waf-hits edge --json
```

| Option | What it does |
| --- | --- |
| `--waf` | `block` answers a match with a `403` page; `log` only logs it (`log waf:<rule>` in `dnz proxy logs`) and lets it through; `off` (on `edit`, alone) turns it off |
| `--waf-sensitivity` | `low`, `medium` (default) or `high`. Try `high` with `--waf log` first |
| `--waf-skip-path` | A path prefix the rules leave alone, e.g. `/admin/editor`; repeat for more |
| `--waf-skip-rule` | A rule id from `dnz proxy waf rules` to leave out; repeat for more. An unknown id is refused |
| `--waf-allow` | An address or range the rules never stop; repeat for more |

`edit` adds the exceptions to what the route has and keeps the rest; the other `--waf-*` flags need
it on first (`--waf block` or `--waf log`). Turning it off and on again starts with no exceptions. A
Traefik or Caddy route refuses it. `routes list` shows it as `WAF (block, medium)` or
`WAF (log only, …)`.

What it caught, from where, and what to do about it ([The WAF page](/proxy/waf-page)):

```bash
dnz proxy waf overview --since 7d -p edge          # totals, attack types, rules, countries, addresses, hostnames
dnz proxy waf events --action block --country CN   # each request it matched, newest first (--ip, --rule, --host, -n)
dnz proxy waf address 203.0.113.9                  # place, network, reverse name, what it set off, blocked where
dnz proxy waf block 203.0.113.9 --host shop.example.com
dnz proxy waf block CN --everywhere                # every DNZ Proxy route with the WAF
dnz proxy waf unblock CN
dnz proxy waf except shop.example.com --skip-rule sqli-union   # or --skip-path /search, --allow-ip 198.51.100.7
dnz proxy waf coverage                             # routes with and without it
dnz proxy waf blocks                               # what was blocked, and in which firewalls
dnz proxy waf locations --download                 # DNZ's country and ASN databases
dnz proxy waf bans                                 # who is banned now: why, until when, where, by whom
dnz proxy waf ban 203.0.113.9 --for 1h             # refuse one address for a while (every DNZ Proxy, or -p edge)
dnz proxy waf unban 203.0.113.9                    # back in now
dnz proxy waf lists --on tor-exit                  # the lists of bad networks; --off, --download
dnz proxy waf campaigns --since 24h                # attacks grouped by network
dnz proxy waf campaign-block AS4134 --everywhere   # its addresses; --ranges for its /24s
dnz proxy waf shields --since 7d -p edge           # shields: each one's CVE, routes and hits, and routes worth a look
dnz proxy routes edit edge wiki.example.com --shield cve-2022-26134   # -ID takes one off, `off` every one; DNZ Proxy only
```

### Rules

A route's [rules](/proxy/rules): redirects, rewrites and header changes when conditions hold, run from
the top down. Every proxy kind takes them; a rule a Traefik or Caddy can't run is refused with its
number and why.

```bash
dnz proxy routes rules list edge shop.example.com          # numbered, each in plain words
dnz proxy routes rules add edge shop.example.com --if 'path starts-with /old/' --redirect 'https://{host}/new/{rest}' --status 301
dnz proxy routes rules add edge shop.example.com --if 'path matches ^/p/([0-9]+)$' --rewrite /post.php --query 'id={1}'
dnz proxy routes rules add edge shop.example.com --if 'country is ID,SG' --if 'header X-Region is asia' --any --rewrite '/asia{path}'
dnz proxy routes rules add edge shop.example.com --set-response-header 'X-Frame-Options: DENY' --at 1 --note 'no frames'
dnz proxy routes rules move edge shop.example.com 3 1       # rule 3 becomes the first
dnz proxy routes rules remove edge shop.example.com 2       # removing the last one turns rules off
```

| Option | What it does |
| --- | --- |
| `--if 'FIELD [NAME] OP [VALUES]'` | A condition; repeat for more (all must hold). Fields: `path`, `query NAME`, `header NAME`, `method`, `country`, `ip`, `host`. Operators: `is`, `is-not`, `starts-with`, `contains`, `matches` (the rest is the regular expression), `exists`, `missing`. Values are comma-separated |
| `--any` | One condition is enough |
| `--redirect URL` | Redirect; `--status 301\|302\|307\|308` (302 by default), `--drop-query` leaves the visitor's query out |
| `--rewrite PATH` | The path sent to the servers; `--query Q` the query (`''` drops it) |
| `--set-request-header 'Name: value'`, `--remove-request-header NAME` | A header the servers get |
| `--set-response-header 'Name: value'`, `--remove-response-header NAME` | A header visitors get |
| `--at N` | The rule's place (1 is first); at the end without |
| `--note TEXT` | A note shown with the rule |

Targets take `{host}`, `{path}`, `{query}`, `{rest}` and `{1}` … `{9}`. `routes list` shows
`rules (3)`; `routes list --type rules` lists the routes with rules.

### Redirects

```bash
dnz proxy routes redirect edge app.example.com --to https://status.example.com --temporary
dnz proxy routes redirect edge app.example.com --to https://new.example.com --keep-path   # a permanent 301
dnz proxy routes redirect edge app.example.com --off                                       # its servers again
```

Every visit to the route's hostnames goes to the address (a `moved` status page on each, replacing
another status page they have). It is a permanent 301 unless `--temporary`: browsers remember a
301, so turning it off wouldn't reach visitors who already got it. `dnz status-page off|on <host>`
switches it without removing it.

### Entry points

The server picks the entry points, the same ones the dashboard's **Add route** uses:

- under **DNZ Proxy**, the proxy's own HTTP and HTTPS entry points;
- under **Traefik**, the ones its API lists, when the proxy has **Traefik API** set;
- under **Caddy**, `web` (:80) and `websecure` (:443).

The one on port 80 serves `http://` and the one on 443 serves `https://`; the command prints which it
picked. Without either, or when no entry point is on that port, it uses `web` and `websecure`.
`--http-entry` and `--https-entry` name them yourself.

### Configuration as code

A proxy's routes, the services and middlewares they use and its route defaults as one YAML file to
keep in Git:

```bash
dnz proxy export edge > edge.yaml                 # passwords by user name only (--secrets: with hashes)
dnz proxy plan -f edge.yaml                       # what would change; nothing is written
dnz proxy plan -f edge.yaml --exit-code           # exit 2 when the proxy differs from the file
dnz proxy apply -f edge.yaml                      # apply it; routes the file leaves out stay
dnz proxy apply -f edge.yaml --prune              # and remove them
```

See [Configuration as code](/proxy/config-as-code).

### Upstreams

Where routes send visits, one list for every proxy. A change reaches every route using the
upstream, on every proxy. See [Upstreams](/proxy/upstreams).

```bash
dnz proxy upstreams list                          # servers, balancing, health check, what uses each
dnz proxy upstreams list --protocol tcp --unused  # only TCP ones nothing uses
dnz proxy upstreams list -q shop --page 2         # a search (name, server, route), a page at a time
dnz proxy upstreams show swarm-service            # with every route (and proxy) using it, and each server's health on the DNZ Proxy nodes
dnz proxy upstreams add swarm-service -t http://10.0.133.31:80 -t http://10.0.133.32:80=2 --sticky --health-check /healthz
dnz proxy upstreams add pg --tcp -t 10.0.0.7:5432
dnz proxy upstreams add canary --split app=9 --split app-next=1
dnz proxy upstreams edit swarm-service --strategy p2c
dnz proxy upstreams edit app-example-com --shared # a route's own upstream becomes a shared one
dnz proxy upstreams merge swarm-service app-example-com
dnz proxy upstreams rm yrdy                       # refused while anything uses it
```

`-t` replaces the servers on `edit`; leave it out to keep them. Each HTTPS server's certificate is
checked unless it is written `https+insecure://HOST:PORT` (any certificate accepted, for that server
only; [Certificate checks per server](/proxy/upstreams#certificate-checks-per-server)). `show` and
`list` write such servers the same way, so a server copied from them keeps its setting.

```bash
dnz proxy upstreams add mixed -t http://10.0.0.20:8080 -t https://app.internal:8443 -t https+insecure://10.0.0.21:8443=2
```

`show` prints each server with its health from the DNZ Proxy nodes' last reports, for example
`(up on 2 of 3 nodes; down on jkt-2: connection refused)`. A server no node checks has none. See
[Server health](/proxy/upstreams#server-health).

An upstream's [connection](/proxy/upstreams#connection-settings) to its servers, the same on every
proxy using it:

```bash
dnz proxy upstreams edit secure-api --server-name api.internal --root-ca ./internal-ca.pem
dnz proxy upstreams edit secure-api --client-cert ./dnz-client.pem --client-key ./dnz-client.key   # mTLS; the key is never shown again
dnz proxy upstreams edit secure-api --connect-timeout 5s --no-http2
dnz proxy upstreams edit pg --proxy-protocol 2       # TCP: send the PROXY protocol
dnz proxy upstreams edit secure-api --transport '{"serverName": "api.internal", "forwardingTimeouts": {"dialTimeout": "5s"}}'
dnz proxy upstreams edit secure-api --no-transport   # back to the defaults
```

`--root-ca`, `--client-cert` and `--client-key` read PEM files on the machine running the CLI and
send their text; `show` lists the settings (client certificates by name and expiry, never their keys).

Servers **from a DNS name** instead of a list: every address of the name is a server, and the list
follows the name. See [Servers from a DNS name](/proxy/upstream-discovery).

```bash
dnz proxy upstreams add swarm --from-dns swarm-nodes.example.local:8080            # DNZ looks it up (its own zones first)
dnz proxy upstreams add api --from-dns api.internal:443 --scheme https --family both --every 60
dnz proxy upstreams add web --from-dns tasks.web:80 --resolve-on proxy             # Docker Swarm tasks: each DNZ Proxy node (and Caddy) looks it up
dnz proxy upstreams add pg --tcp --from-dns db.internal:5432 --tls
dnz proxy upstreams edit swarm --every 120         # the name's other settings stay
dnz proxy upstreams edit swarm -t http://10.0.0.11:8080   # listed servers again
dnz proxy upstreams discover swarm                 # look the name up now (nothing saved); for tasks.<service>, what each node found
```

| Option | What it does |
| --- | --- |
| `--from-dns NAME:PORT` | Every address of `NAME` is a server, reached on `PORT` |
| `--resolve-on` | Who looks the name up: `dnz` (default: DNZ's own DNS, its zones first) or `proxy` (each DNZ Proxy node and Caddy, for `tasks.<service>`). `proxy` is for HTTP upstreams and is refused on a Traefik proxy |
| `--scheme` | HTTP: how the servers are reached, `http` (default), `https`, `https+insecure` (https, any certificate accepted) or `h2c` |
| `--family` | The addresses taken: `v4` (A, default), `v6` (AAAA) or `both` |
| `--every SECONDS` | DNZ looks the name up again after its TTL, but not sooner than this (5 to 3600, default 30) |
| `--tls` | TCP: the servers speak TLS |

`list` shows `NAME:PORT (3 found)` (or `each proxy`) as the servers; `show` the name, how many servers
it gave and when, and the error while lookups fail (the last servers stay).

### Middlewares and firewalls

What happens to a visit on its way, one list for every proxy. A change reaches every route running
it, on every proxy. See [Middlewares and firewalls](/proxy/middlewares).

```bash
dnz proxy middlewares list                         # shared ones: type, the proxy kinds that run it, what uses it
dnz proxy middlewares list --own --unused          # routes' own switches too; only the ones nothing uses
dnz proxy middlewares show strip-api               # its settings and every route (and proxy), chain and route defaults using it
dnz proxy middlewares usage office
dnz proxy middlewares add strip-api --settings '{"stripPrefix": {"prefixes": ["/api"]}}'
dnz proxy middlewares add office-only --tcp --settings '{"ipAllowList": {"sourceRange": ["10.0.0.0/8"]}}'
dnz proxy middlewares add office --file ./office-firewall.json   # {"dnzFirewall": {"rules": [...]}}
dnz proxy middlewares edit strip-api --rename strip-v1 --description "Old API clients"
dnz proxy middlewares edit app-example-com-headers --shared   # a route's own switch becomes a shared middleware
dnz proxy middlewares merge office office-edge2    # everything using office-edge2 uses office
dnz proxy middlewares rm strip-v1                  # refused while anything uses it
dnz proxy firewalls list                           # every firewall, its rule count and what uses it
dnz proxy firewalls show office                    # its rules, in order
```

`--kind` defaults to the type `--settings` holds. A TCP route picks TCP middlewares with
`dnz proxy routes add-tcp … --middleware office-only`.

### Route defaults (DNZ Proxy)

What every route of a DNZ Proxy gets, live on its nodes:

```bash
dnz proxy defaults edge                           # show them
dnz proxy defaults edge --redirect-https on --compress on --security-headers on --firewall office
dnz proxy defaults edge --firewall none
```

See [Route defaults](/proxy/dnz-proxy#route-defaults).

### Settings (DNZ Proxy)

A DNZ Proxy's own settings: joining without approval, the TTL of proxied answers, checking the nodes'
ports, cache sizes, request log lines per second, the GeoIP database and peak concurrency.

```bash
dnz proxy settings edge                           # show them
dnz proxy settings edge --peak-tracking on        # nodes count the most requests in progress and connections open at once
dnz proxy settings edge --peak-tracking off       # stop counting, within seconds
dnz proxy settings edge --server-header origin    # visitors get the origin's Server header
dnz proxy settings edge --server-header dnz       # "Server: dnz" instead (the default for new proxies)
dnz proxy settings edge --request-id on           # a DNZ-Request-Id on every request (off by default)
dnz proxy settings edge --bans on --ban-blocks 20 --ban-within 5 --ban-minutes 60 --ban-scope proxy   # ban an address the WAF keeps blocking (off by default)
```

[Peak concurrency](/proxy/dnz-proxy#peak-concurrency) is off by default, since counting it adds a
little work to every request; turn it off again if the nodes get slower. The other settings are
changed on the proxy's **Settings** tab.

### Certificates

DNZ's automatic certificates for DNZ Proxy routes:

```bash
dnz proxy certs show                              # on or not, the account, the credentials in use
dnz proxy certs list [-q shop] [--state failed]   # the certificates, in use first, a page at a time
dnz proxy certs setup --agree --email admin@example.com   # once: a Let's Encrypt account (accepting its agreement)
dnz proxy certs setup --account "Let's Encrypt"   # or one DNZ already has
dnz proxy certs wildcards on                      # one wildcard per domain (default); off: one certificate per name
dnz proxy certs check edge app.example.com shop.example.org
dnz proxy certs credential shop.example.org --cloudflare-token …
dnz proxy certs credential shop.example.org --rfc2136 192.0.2.53:53 --key-name acme. --secret …
dnz proxy certs credential shop.example.org --webhook https://hooks.example.com/acme --suffix example.org
dnz proxy certs upload --cert fullchain.pem --key privkey.pem   # your own certificate; DNZ asks no CA for its names
```

`certs check` says per name how DNZ would prove it: DNZ's own zone, a Cloudflare connection, a DNS
credential, HTTP-01 through the nodes, an uploaded certificate covering it (`uploaded`), DNZ's private
CA for an internal name (`ca`), or **needs a way**. `certs credential` adds and removes a test TXT record first and keeps the credential only when
that works. `certs upload` takes a certificate you bought or got from your own CA (PEM chain, leaf
first, and its key); nodes serve it as it is, and it isn't renewed. `DNZ_CLOUDFLARE_TOKEN` and
`DNZ_ACME_SECRET` keep secrets off the command line. See
[Automatic certificates](/proxy/certificates#automatic-certificates).

DNZ's private certificate authority for internal names has its own command, `dnz ca`: see
[Private CA](/cli/ca). A route asks for it with the resolver `private-ca`; internal names on the `auto`
resolver get a certificate from it by themselves.

## DNZ Proxy nodes

```bash
dnz proxy nodes                                   # every node: proxy, state, addresses, version, config, CPU, memory
dnz proxy nodes list -q jkt --page 2              # a page of the nodes in a proxy (waiting ones always listed)
dnz proxy nodes show jkt-1                        # one node: its report and its server's CPU, load, memory, disk
dnz proxy nodes addresses jkt-1                   # its addresses: in DNS or not, to all clients or one view, set by whom
dnz proxy nodes address jkt-1 10.0.0.5 --view Internal # add a LAN address answered only to the clients in the view Internal
dnz proxy nodes address jkt-1 203.0.113.10 --dns off   # keep an address but leave it out of DNS (--dns on: back in)
dnz proxy nodes address jkt-1 10.0.0.5 --remove
dnz proxy nodes update jkt-1                      # update it to DNZ's version: out of DNS, the signed release, restart, back
dnz proxy nodes update --proxy "Edge JKT" --wait  # every node of the proxy that can, one at a time; follows it, fails if it stops on a node
dnz proxy nodes update jkt-1 --allow-outage       # go ahead with a proxy's last healthy node: its sites go down while it restarts
dnz proxy nodes update --status --proxy "Edge JKT" # what an update would do per node (by hand: the command), and how the last one went
dnz proxy nodes update --stop --proxy "Edge JKT"  # no further node is asked
dnz proxy approve jkt-1 --proxy "Edge JKT" --ipv4 203.0.113.10
dnz proxy ignore node-10-0-0-9                    # turn a waiting node away
dnz proxy drain jkt-1                             # out of DNS answers, still serving
dnz proxy drain jkt-1 --undo
dnz proxy remove jkt-1                            # it can't connect any more
```

`dnz proxy show` prints whether proxying is on, the proxies and the **connect key** new nodes join
with. New nodes wait for approval; they can only join DNZ Proxies. `approve` takes:

| Option | What it does |
| --- | --- |
| `-p`, `--proxy` | The proxy it serves, by name or id. Required |
| `--ipv4`, `--ipv6` | Where visitors reach it; DNS answers with these (default: what the node asked for) |
| `--name` | A new name for the node |

Nodes are named by name or id.

`nodes` shows each node's CPU (a share of the CPUs it may use: its container's limit, else the
machine's) and its process's memory. `nodes show` adds the load average, the container's and the
machine's memory, the free disk and TCP sockets, from the node's last report (see
[Servers](/proxy/dnz-proxy#servers)). With `--json`, `report.system` holds the raw numbers. While the
proxy counts [peak concurrency](/proxy/dnz-proxy#peak-concurrency), `nodes show` also has a
**Concurrency** line: `3 requests in progress, 12 connections open (at most 9 and 14 in the last 5 s)`.

### Clearing the cache

`dnz proxy purge` (or `dnz proxy clear-cache`) clears cached answers on every node of a proxy;
`dnz proxy routes clear-cache` does it for one route's hostnames:

```bash
dnz proxy purge "Edge JKT"                        # every cached answer
dnz proxy purge "Edge JKT" --host app.example.com --prefix /assets
dnz proxy purge "Edge JKT" --url https://app.example.com/logo.png
```

`--prefix` needs `--host`.

### Traffic and request logs

Each node keeps its own analytics. These commands ask the nodes, like **Proxy → Analytics**, and
say on stderr which nodes didn't answer.

```bash
dnz proxy analytics                               # last 24 h, every proxy: totals, active users now (per proxy), most requested URLs, top lists,
                                                  # and what the web application firewall blocked and logged, with its top rules and addresses;
                                                  # "Peak concurrent: at most N requests in progress, M connections open" once a proxy counts it
dnz proxy analytics -p "Edge JKT" --since 7d      # 1h, 6h, 24h, 7d or 30d
dnz proxy analytics --host app.example.com -n 50  # that hostname's 50 busiest paths
dnz proxy logs                                    # newest 50 request log lines
dnz proxy logs --host app.example.com --status 5xx -q /api
dnz proxy logs --client 198.51.100.7 -n 200
dnz proxy logs -q 8f2a1b3c4d5e6f70                # one request, by its DNZ-Request-Id (each line ends with it)
dnz proxy logs -f                                 # follow, oldest first (with --json: one JSON line each)
```

The **Peak concurrent** line is the busiest minute (or hour) with the nodes' peaks added up, so at
most that many. Peaks are counted per node, not per hostname: with `--host` the line says so.

### Waiting rooms

A waiting room is a `dnzWaitingRoom` middleware (see
[Waiting room](/proxy/dnz-proxy#waiting-room-dnzwaitingroom)). `set` adds one or changes the settings
you give, keeping the rest. Put it on a route with `dnz proxy route … -m <name>` or in the proxy's
page.

```bash
dnz proxy waiting-room set "Edge JKT" sale-line --max-active 500 --session 5m \
  --bypass-path /api/ --bypass-path /static/ --allow-user-agent UptimeRobot
dnz proxy waiting-room set "Edge JKT" sale-line --queue-all   # before the launch: everyone waits
dnz proxy waiting-room set "Edge JKT" sale-line --open        # open: the line goes in first
dnz proxy waiting-room set "Edge JKT" sale-line --redis redis:6379   # one line across all nodes
dnz proxy waiting-room show                       # visitors in, the limit and waiting, per hostname
dnz proxy wr ls -p "Edge JKT" --json
```
