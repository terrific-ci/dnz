title: "Status pages"
description: "Switch a proxied host to maintenance, blocked, moved and more from the terminal, with schedules and allowed addresses."
---

These commands match **Proxy → Status pages** in the dashboard: a host a proxy serves shows its
visitors a status page instead of the backend. For what the statuses do, see
[Status pages](/proxy/status-pages).

`dnz status-pages` is an alias for `dnz status-page`. Hosts are named as they are, e.g.
`app.example.com` or `*.example.com`.

## Permissions

- Superadmins manage every host.
- Others manage the hosts in zones where they have `records.write`, and see those of zones they can
  read.
- A host in none of DNZ's zones is superadmin-only.
- [Several routes at once](#several-routes-at-once) and [scheduled maintenance](#scheduled-maintenance)
  also need **Manage proxies** (`proxy.manage`).

## Finding a host

```bash
dnz status-page kinds                                   # the statuses, their codes and titles
dnz status-page hosts                                   # names a proxy serves, the proxies, and their status
```

Only names a proxy serves can have a status: proxy the record, or add a route with
[`dnz proxy route`](/cli/proxy#proxy-routes), first.

## Setting a status

```bash
dnz status-page set app.example.com maintenance --for 2h --allow 203.0.113.7,10.0.0.0/8
dnz status-page set app.example.com maintenance --from "2026-10-25 22:00" --until "2026-10-26 01:00" \
  --message "We're upgrading the database. Back by 01:00." --link https://status.example.com
dnz status-page set old.example.com moved --to https://new.example.com --keep-path
dnz status-page set promo.example.com moved --to https://shop.example.com/sale --temporary  # a 302
dnz status-page set beta.example.com coming_soon --off  # saved, but off for now
```

The status is one of `maintenance`, `coming_soon`, `unreachable`, `blocked`, `unauthorized`,
`suspended`, `rate_limited`, `geo_blocked`, `moved` or `gone`.

| Flag | Meaning |
| --- | --- |
| `--title` | Instead of the status's usual title |
| `--message` | Instead of the status's usual message |
| `--from` | Starts at this time (default: now) |
| `--until` | Ends at this time; drives `Retry-After` and "Expected back" (default: until turned off) |
| `--for` | Ends this long after it starts: `30m`, `2h`, `1d` (instead of `--until`) |
| `--allow` | IPs and CIDRs that reach the backend as usual, comma-separated |
| `--link` | The *More information* button, e.g. `https://status.example.com` |
| `--to` | `moved`: the new address |
| `--keep-path` | `moved`: keep the path and query (`/a?b` → `<to>/a?b`) |
| `--temporary` | `moved`: a temporary 302 instead of the permanent 301 (browsers remember a 301, so turning it off wouldn't reach visitors who saw it) |
| `--off` | Save it turned off |

Times are RFC 3339 (`2026-10-25T22:00:00+07:00`) or `"YYYY-MM-DD HH:MM"` in this machine's time
zone. `--for` counts from `--from`, or from now.

<Note>
  `set` creates the host's status, or **replaces** the one it has with exactly what the command
  gives. Options left out go back to their defaults (the usual title and message, no window, nobody
  allowed through), and the status is on unless `--off` is given.
</Note>

## Several routes at once

```bash
dnz status-page set app.example.com maintenance --also api.example.com --also shop.example.com --for 2h
dnz status-page set app.example.com maintenance --routes     # every hostname of app.example.com's route
dnz status-page set app.example.com maintenance --also old.example.com --include-redirects
```

With `--also` or `--routes`, the status goes on **every hostname of the routes** holding the hosts,
on every proxy serving them, in one batch, as **Set status page** in the Routes bar does
([Several routes at once](/proxy/status-pages#several-routes-at-once)).

| Flag | Meaning |
| --- | --- |
| `--also HOST` | Another route, by one of its hostnames; repeat for more |
| `--routes` | The host is a route's hostname: the status goes on every hostname of that route |
| `--include-redirects` | Also on redirect routes' hostnames, which ends their redirect. Without it they keep redirecting |

The other flags of `set` work as above, except `--off`: a batch sets the statuses on. It is all or
nothing: if one hostname can't take the status, none changes, and the command prints each route's
reason. To take them all back to normal, `dnz status-page clear` each host, or pick them on
**Proxy → Routes** and use **Back to normal**.

## Watching, turning off and removing

```bash
dnz status-page list                                    # host, status, state, schedule, proxies, allowed
dnz status-page show app.example.com
dnz status-page off app.example.com                     # kept; `on` brings it back
dnz status-page on app.example.com
dnz status-page clear app.example.com                   # remove it (`rm`)
```

**State** is `active` (visitors see the page), `scheduled` (starts later), `ended` (its window is
over) or `off`. `list` and `show` print times in this machine's time zone. `clear` asks first;
`--yes` skips the question (needed without a terminal), and `--json` prints the API's answers.

## Scheduled maintenance

Maintenance that repeats, such as every Sunday at 22:00 for two hours (**Proxy → Status pages →
Scheduled maintenance**). See [Scheduled maintenance](/proxy/status-pages#scheduled-maintenance) for
what it does.

```bash
dnz proxy maintenance add "Weekly backups" --hosts app.example.com,api.example.com --days sun --at 22:00 --for 2h
dnz proxy maintenance add "Patch night" --hosts '*.shop.example.com' --days mon-fri --at 23:30 --for 90m \
  --from 2026-11-01 --until 2026-12-31
dnz proxy maintenance list                     # when, hostnames, on now or next (`ls`)
dnz proxy maintenance upcoming --days 14       # the occurrences of the next 1 to 31 days (default 7)
dnz proxy maintenance show "Weekly backups"
dnz proxy maintenance edit "Weekly backups" --at 23:00 --no-quiet   # only what you pass changes
dnz proxy maintenance edit "Weekly backups" --off                   # kept, not running; --on again
dnz proxy maintenance rm "Weekly backups"
```

| Flag | Meaning |
| --- | --- |
| `--hosts` | Hostnames it covers, comma-separated; `*.example.com` covers one label below |
| `--days` | `mon` … `sun`, `weekdays`, `weekend`, `every`, or a range like `mon-fri`; comma-separated |
| `--at` | When it starts, `HH:MM` **in the server's time zone** (not this machine's) |
| `--for` | How long it lasts: `90m`, `2h`, `1h30m`; it may run past midnight |
| `--from`, `--until` | Its first and last day (`YYYY-MM-DD`); default from now, with no end |
| `--title`, `--message` | Instead of the maintenance page's usual title and message |
| `--allow` | IPs and CIDRs that get the sites as usual, comma-separated |
| `--no-quiet` | Uptime monitors of the hostnames alert as usual during it |
| `--not-public` | Keep it off the public status page's *Scheduled maintenance* |
| `--off` | Save it turned off (`edit --on` turns it on again) |

Windows are named by their name; `edit --rename` gives one a new name.
