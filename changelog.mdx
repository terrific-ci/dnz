The latest release is **v1.23.0**, released October 30, 2026. To install or upgrade to it:

```bash
docker pull terrificci/dnz:1.23.0
docker pull terrificci/dnz-proxy:1.23.0   # a server that only runs DNZ Proxy
curl -fsSL https://raw.githubusercontent.com/terrific-ci/dnz/main/install.sh | sh -s -- --version 1.23.0
```

The `latest` image tag and the install script without `--version` always get this release; see
[Install](/deploy/install).

<Update label="v1.23.0" description="October 30, 2026" tags={["Latest"]}>

- **Uptime for a group of routes:** Add monitor → A group of routes watches a whole group from Proxy → Routes. Every route in it gets its own monitor, routes that join the group are watched within a minute and ones that leave aren't. Changing the watch changes all of its monitors (`dnz uptime watch`).
- **Helpdesk role:** a new permission, Post incidents, and a built-in Helpdesk role holding only it: open incidents on the public status page, post their updates and resolve them, without managing monitors or anything else.
- **Public status page on its own hostname, in one step:** pick a proxy and DNZ's address, and saving makes the route and the DNS record right away; turning the page off removes them again. The card shows the name's DNS records and routes, fills in DNZ's address from Settings → General → Device address, and warns about an address that would send visitors round in a loop (`dnz uptime page set --proxy … --dnz-address …`).
- **Public status page look:** it now looks like DNZ's other visitor pages (maintenance, moved and the like), in light and dark.
- **Route groups:** a New group button next to the filters (a name and the routes to put in it), and in By group, drag a route onto another group to move it, or onto No group or New group… while dragging.
- **Menus:** items that open a submenu (Move to group, a route's proxies) now line up with the others.

</Update>

<Update label="v1.22.0" description="October 30, 2026">

- **Web application firewall:** DNZ Proxy routes can turn on ready-made rules against common attacks (SQL injection, cross-site scripting, path traversal, Log4Shell, attack tools and more), at Low, Medium or High sensitivity, blocking or only logging, with exceptions for paths, rules and addresses. Matches show in Proxy → Analytics (rules, addresses, paths attacked) and as a count on the route in the Routes list.
- **Route rules:** redirect, rewrite and change headers when conditions hold (path, query, header, method, country, address, hostname), right in the route dialog, with no Advanced editing. Traefik and Caddy routes get them too wherever those proxies can express them.
- **Uptime and a public status page:** monitors for any URL and for DNZ Proxy services, incident history with your own updates, 30 and 90-day uptime bars, and a public page to share with your users, with your logo.
- **Proxy alerts:** notifications through your notification providers when attacks spike, an origin or a DNZ Proxy node goes down (and when it's back), or a certificate fails to renew.
- **Route history:** every change to a route is kept, with who made it and what changed; restore any earlier version in one click, including a deleted route.
- **Proxy configuration as code:** export a proxy's routes as YAML, see what a file would change before applying it, and apply it (`dnz proxy export`, `plan`, `apply`), for keeping routes in Git.
- **Encrypted DNS certificate from DNZ:** DNZ can get and renew the certificate for DNS over TLS and HTTPS itself (Settings → General → Encrypted DNS, or `dnz settings certificate`).
- **Visitors:** a Visitors (24h) column with an hourly chart on the Routes and Zones pages, and Active users now in Proxy → Analytics, for all proxies or one.
- **Routes:** groups (a By group view and Move to group), a type filter (redirects, HTTP only, failing certificates, WAF and more), pages of 25, 50 or 100 routes, an "All proxies" choice when adding a route, and the route dialog's switches grouped by purpose.
- **Routes on several proxies:** a route that uses a service from the list now uses the service of the same name on each proxy instead of a second copy of the same servers; "Use … on …" in the route's menu fixes routes saved before.
- **Replication:** each replica shows how far each part is in sync (zones, record details, settings, accounts), with a percentage, when you open it.
- **Proxy analytics:** visits to DNS filtering's block page no longer show up as requests in the proxy's request log; they are counted as one row, "Blocked by DNS filtering". A visitor who passed the "under attack" check is no longer counted as challenged.
- **Menu:** DNZ Proxy's own sections (Analytics, Nodes, Certificates) appear once one of your proxies is a DNZ Proxy.
- **Faster DNS:** up to about 10% more queries a second, with less CPU per query and lower latency.
- **CLI, MCP and API:** everything above is also in `dnz` (for example `dnz proxy routes rules`, `group`, `history`, `dnz uptime`, `dnz proxy waf rules`) and in the MCP tools.

</Update>

<Update label="v1.16.0" description="October 27, 2026">

- **Block page:** DNS filtering can point blocked names at a proxy that shows visitors a "Blocked" page instead of a failed connection. On DNZ Proxy (also over HTTPS, with a certificate authority your devices trust), and on Traefik and Caddy over plain HTTP. Set up on the Filtering page or with `dnz filter block-page`.
- **Live Capture:** DNS → Live Capture streams the queries matching a few keywords as they are answered, grouped by domain or as a live list, and blocks a domain or name from the results (`dnz capture`).
- **Query log:** kept in one file per day on each server, so a long search can no longer slow down sign-in, the dashboard or DNS. At most two searches run at once per server; in a cluster, Query Logs gathers every server's rows. Searches cover the last 24 hours by default, with a range picker (`dnz logs --range|--since|--until`). Queries logged before the upgrade are not carried over; the charts and top lists keep their history.
- **Routes:** a custom headers switch on every proxy kind, to set or remove headers on requests and answers.
- **Visitor pages:** DNZ Proxy shows styled pages when a password, rate limit, allow list or firewall turns a visitor away (Caddy for the password and allow list), and the "under attack" check gets the same style.
- **Records:** filter by view, and a searchable type picker that also matches what a type holds ("ipv6" finds AAAA).
- **Find:** Cmd+K finds settings inside pages by the words people search for, and can clear the DNS cache.
- **Memory:** a new setting under Settings → General decides when DNZ releases the cache of its log files (`dnz settings file-cache`). Fixed: a Query Logs page left open on Live kept gigabytes of the log in the container's memory, and the Server tab missed the container's memory on hosts with mixed cgroup versions.
- **Rate limiting:** RRL's exempt networks are entered as tags.
- **Replication fix:** a joining secondary no longer keeps its own empty *Default* division beside the primary's.

</Update>

<Update label="v1.15.0" description="October 26, 2026">

<Update label="v1.5.0" description="October 23, 2026">

- **DNS server:** authoritative zones over UDP and TCP with EDNS, CNAME chasing, ALIAS records (CNAME flattening at the apex), automatic PTR, DNS cookies and NSID, record types including HTTPS/SVCB, CAA, TLSA, SSHFP, NAPTR, DS, URI, DNAME and LOC, a per-client rate limit and response rate limiting (RRL).
- **Records and zones:** switch records on and off, a default TTL per zone, comments and tags, bulk edits, several records added at once (`dnz record add-many`), and zone import and export (a zone file, or from Cloudflare).
- **Split-horizon DNS:** views answer different client networks with different records.
- **Forwarding:** forwarding strategies with failover and monitoring of the forward DNS servers, encrypted upstreams (DNS over TLS, HTTPS, QUIC and HTTP/3), conditional forwarding, forward rules by client network in a drag-and-drop order (first match wins), serve-stale and prefetch, EDNS Client Subnet and DNS64. Zones can forward the names they don't have to the upstreams. Diagnose an upstream step by step in the UI or with `dnz forwarding diagnose`.
- **Recursive resolution:** DNZ can resolve from the root servers itself, and validates DNSSEC on forwarded and recursive answers.
- **Encrypted DNS:** DNZ serves DNS over TLS, HTTPS, QUIC and HTTP/3 to its clients.
- **DNSSEC signing:** local zones are signed (NSEC3, Ed25519 or RSA, separate KSK and ZSK), with automatic key rollover and CDS/CDNSKEY.
- **Dynamic DNS:** DNS UPDATE (RFC 2136) with TSIG update keys per division (in the UI and `dnz update-key`), and DynDNS2 for routers and DDNS clients.
- **Filtering:** blocklists per division, safe search, parental control, schedules and per-client rules; subscribe to response policy zones (RPZ) and serve your blocklists as one.
- **GeoDNS and traffic steering:** answers by location, weighted answers and health checks for A/AAAA records.
- **Replication:** zone transfers, NOTIFY, catalog zones and DNZ secondaries, with a Replication page that finds DNZ servers on the network.
- **Clustering and databases:** SQLite, Postgres or MySQL (`dnz db migrate-from-sqlite` moves an install over), and several DNZ servers sharing one Postgres or MySQL database.
- **Zone history and change approval:** every version of a zone with diffs and rollback, change requests and approval policies (`dnz zone history|diff|rollback`, `dnz change`).
- **Overview:** an hourly query chart, top names and clients, queries per client network, an "Answered by" breakdown, 24h/7d/30d/90d ranges, the server's own usage and a request flow diagram; `dnz stats`.
- **Alerts:** notification providers for incidents, traffic alerts and a daily summary.
- **Threat detection:** detectors over the query stream with findings per client and per domain, evidence, threat feeds (abuse.ch and HaGeZi presets), alerts and automatic blocking.
- **DHCP and IPAM:** leases from Kea, dhcpd and Windows DHCP become records, DHCID rules for DNS UPDATEs, and an IPAM view of subnets and conflicts (DNS → DHCP & IPAM, `dnz dhcp`, `dnz ipam`).
- **Cloudflare:** a connection per division with an API token or Sign in with Cloudflare, and import of a Cloudflare zone's records (all of them, or only the ones ticked) into local DNS.
- **Proxied records:** send a name through a reverse proxy. Traefik is detected and approved, set up with a copy-paste guide, and its routers, services and middlewares are managed from DNZ; records can be made from Traefik's own routers, Caddy's sites can get DNS records too, and one record can go through several proxies.
- **DNZ Proxy:** DNZ's own reverse proxy. Nodes join a proxy and get their configuration from DNZ, with caching, firewall rules, an "under attack" check, rate limits shared through Redis, client certificates, TCP and UDP routing, certificates issued and renewed by DNZ over ACME, and traffic analytics with a request log. Run nodes from the `terrificci/dnz-proxy` image, on Docker Swarm or on DNZ's own server; manage them with `dnz proxy`.
- **Topology map:** the whole setup on one canvas.
- **Kubernetes:** an ExternalDNS webhook provider (`dnz externaldns-webhook`), with a guide.
- **Monitoring:** Prometheus metrics on an address of their own or through the API with a token, a Grafana dashboard, alert rules and a monitoring compose file.
- **Setup and health:** a first-run setup wizard (also `dnz setup`), a health check with copy-paste fixes and scheduled alerts (`dnz doctor`), a Device address so setup guides show the right address when DNZ runs in Docker, and factory reset from the UI or the CLI.
- **Backups:** archives of the whole install to a folder, S3-compatible storage or SFTP, with schedules, retention and restore (also from the setup page).
- **Accounts and security:** divisions, users, roles, API tokens (which can also answer ACME DNS-01 challenges) and an audit log; hardened sign-in, sessions and HTTP headers.
- **CLI and configuration:** a TOML config file, a CLI-only mode, and `dnz` commands for everything in the web UI.
- **Install:** Docker images on Docker Hub (`terrificci/dnz` and `terrificci/dnz-proxy`) and Linux release binaries that need glibc 2.34 or newer.

</Update>
